负载归属要按 rank 隔离，长 prefill 不能被误判失活

截至 2026-10-20 08:57（Asia/Shanghai）：SMG 修正跨 rank 负载归属与长 prefill 静默判定，并把 tokenizer 打包移出事件循环；SGLang、vLLM 继续收紧 KV 恢复和滑窗块的正确性边界。文内 PR 时间均为北京时间；main 合并不代表正式版本已包含，作者测试未由本报独立复现。

01

今日最重要

  1. SMG：其他 rank 的推送不能替静默 rank 续命 — #3983 于 10 月 20 日 03:51 合并。虚拟 DP worker 共用 backend 事件流时，现在拒收其他 rank 和负 rank 的负载，避免错误更新本 rank 的 liveness、freshness 与指标，进而抑制本应继续的回退轮询。min-token 选择限定在绑定 rank，缺失遥测返回 None。判断：昨日 #3968 处理轮询新值被旧推送覆盖；今天进一步修正数据归属。验收要让 DP8 中仅部分 rank 持续推送，确认静默 rank 仍被单独轮询。作者单测与 clippy 已过，真实多 DP GPU 端到端尚未验证。
    smg #3983
  2. SMG：长 prefill 放宽静默阈值，同时承担更慢的冻结发现 — #3981 于 10 月 20 日 03:52 合并。对上报 engine_silence 的 step-reporting 路径，按 pending prefill 与实测速率（冷启动使用先验并设上限）增加静默容忍量，避免长多模态单步超过默认 3 秒即被 veto。已有 veto 仍需引擎产生输出才解除。判断：作者 CPU mock 的 72.9k-token、9.1 秒 prefill 中，10 次请求的 veto 从 9 次变为 0；长请求冻结发现也从 3 秒延长到 15 秒。不能只看误剔除下降，应同时验收真实视频请求和冻结故障。Python 不推该字段，不能称所有路径都已覆盖。
    smg #3981
  3. SMG：tokenizer 首次打包不再占住 Python 事件循环 — #3989 于 10 月 20 日 00:25 合并。SGLang、TokenSpeed、MLX 的 GetTokenizer 压缩与哈希移至 asyncio.to_thread；四种 Python servicer（含原已 offload 的 vLLM）共享 single-flight 与内存缓存，失败不缓存，单个等待者取消不取消公共构建。判断：多网关同时启动时，应同时压测 token 流、health 与 abort，而非仅测 ZIP 接口。作者测得的 loop stall 降低不是 GPU 吞吐结果；缓存假设模型目录在 servicer 生命周期内固定，Rust 路径也未改成同样缓存。
    smg #3989

AI 推理 / 系统工程动态

SGLang #42702 于 10 月 20 日 02:55 合并，为 PD retraction 恢复 KV 与在飞 forward 的并发写入补上 stream 等待，覆盖 host_pool 和 cpu_tensor 恢复路径。vLLM #60767 于当日 04:25 合并，将 V2 runner 的 SWA forward block table 中窗口外已释放块置为 null，避免读取无效块后即使被 mask 仍发生 NaN 传播。

判断：恢复完成的含义必须包含写入顺序，而不只是拷贝已提交。SGLang 有真实 GPU 确定性单测，尚无 PD 端到端或性能测试，RDMA prefill 写入预分配 slot 不在此修复范围；vLLM 不覆盖 V1 runner 与 CP。先做正确性与故障注入，不把作者特定 serving build 的接受率变化泛化为升级收益。

行动建议

  1. 逐 rank 记录 pushed load、轮询时间与策略输入，注入单 rank 静默和负 rank 记录，确认其他 rank 不会替其刷新健康状态。
  2. 用真实长视频 prefill 同时测误 veto 与冻结发现时间；把延迟阈值的上限和回滚条件写进发布验收。
  3. 并发启动多个网关下载 tokenizer，同时检查 token 流、health、abort 延迟及取消后的共同构建行为。
  4. 对 PD retraction 恢复与 forward 重叠建立确定性回归，并对 SWA 已释放窗口块填入异常值，检查是否仍传播 NaN。
  5. 核对 tag、镜像 commit 与工具解析回归结果，避免将主干修复当作现有稳定包已具备的能力。
