RL Rollout 调度开始超越 Prefix Locality

今天最值得关注的是混合 RL rollout 对 KV 容量与驻留时间提出的新调度要求，以及集群级持续性能回归正在成为推理基础设施的基本能力。

01

今日最重要

  1. MISA-T 面向混合 RL Rollout 调度 — 论文把 session admission、workload-aware KV 容量分配与驻留时间核算放入路由层；在 Step3.7 与 Qwen3.6-35B-A3B 上，相比调优后的 cache-aware vLLM Router，rollout 吞吐分别提高 53.3% 和 43.6%。判断：RL 推理服务的目标函数应从命中率与负载均衡升级到 KV 时间占用、训练分布保真和迭代时长。
    MISA-T 论文
  2. ClusterBench 做集群级持续回归 — 框架覆盖 CPU、GPU、内存、互连和 I/O，以统一作业周期性验证整套集群；论文观察到同规格节点样本间性能差异可达 5%。判断：驱动、Kernel、固件或调度升级不能只在单节点冒烟，应建立跨节点、跨时间的基线。
    ClusterBench 论文
  3. ImpactHO 探索重要性感知 KV 迁移 — 面对边缘节点切换的有限回传窗口，论文优先传输高价值 KV；在 500ms 窗口内报告 93.7% 以上平均准确率。判断：跨节点 KV 不必默认全量搬运，部分缓存降级值得进入 P/D、故障迁移和边缘推理实验。
    ImpactHO 论文
  4. 主流项目今日无新大版本 — 最近 24–48 小时未发现 vLLM、SGLang、Go 或 Rust 的新正式大版本，因此不重复堆砌昨日发布。判断：低变化日更应把注意力放在高价值论文与可验证工程方法，而不是用旧闻填满版面。
    vLLM ReleasesSGLang Releases
02

AI 推理 / 系统工程动态

MISA-T 指出 Prefix-aware routing 无法控制异构 rollout session 对 KV 容量的竞争。RLVR、RLHF 与 Agentic rollout 的序列结构、交互模式和 KV 驻留时长不同，如果共用异步推理服务，长驻留会话可能挤压短 rollout，并改变 trainer 期望的 workload mixture。ImpactHO 从另一侧说明：带宽不足时，可按信息重要性选择性迁移 KV，而不是把每个 token 等价处理。

判断：下一代 Router 需要同时感知 session admission、KV-residency、训练 workload 配比与部分 KV 降级，单纯追求 Prefix Cache 命中率已经不够。

后端与云原生 / Rust / Golang 动态

Kubernetes 最新仍为 1.37.0-rc.0，生产集群不应直接升级；1.34 将于 8月27日进入维护期。Go 1.27 官方页面仍标注 DRAFT，泛型方法与 encoding/json/v2 只宜进入实验 CI。Rust 官方最新稳定仍为 1.97.1，本日没有足够重大的语言更新。

判断：控制面升级应优先验证 Device Plugin、Kueue、Gateway、RDMA/NCCL 与监控链路，而不是只跑普通 Pod 冒烟。

04

值得看的项目 / 论文 / 工具

  1. Scheduling Mixed RL Rollouts Beyond Prefix Locality — 直接映射到现有 Router 的 admission 与 KV-accounting 设计，并给出 workload 保真指标。判断：今天首选精读，尤其适合正在做 Prefix Router 或 RL rollout serving 的团队。
    arXiv
  2. ClusterBench — 以全节点同一作业和空间/时间对比构建持续性能基线。判断：可借鉴到 GPU 集群验收、版本升级回归和慢节点识别。
    arXiv
  3. ImpactHO — 把 KV token 重要性转换成部分缓存精度与带宽分配问题。判断：适合作为跨机 KV 降级策略的研究起点，暂不宜直接照搬生产。
    arXiv
05

产业趋势与投资信号

最近 24–48 小时未核验到足够重大且有一手公告支持的推理基础设施融资或并购。更重要的产品信号是 RL post-training 正把推理服务从在线 API 变成训练流水线内的关键资源调度器；KV residency、workload mixture 保真和 iteration time 会直接决定训练成本。

判断：下一轮平台溢价可能来自可证明的 RL rollout goodput、集群回归检测和跨节点 KV 降级能力，而不是单次峰值 tokens/s。

06

行动建议

  1. 给现有 Prefix-aware Router 增加每类 workload 的 KV-residency 分布、admission 等待时间，以及实际消费 mixture 与 trainer target 的偏差。
  2. 用真实 RLVR、RLHF、Agent 混合 Trace 对比仅 Prefix 路由和 KV 容量/驻留时间感知路由的吞吐、P99 与 iteration time。
  3. 建设集群级连续基准；每次驱动、Kernel、固件或 Kubernetes 升级后，同批运行 GPU、内存、互连与 I/O 测试并按节点追踪漂移。
  4. 为跨机 KV 传输做 25%、50%、75% 部分缓存降级实验，测量精度、带宽和恢复时延曲线。
  5. Kubernetes 1.37 rc0 与 Go 1.27 只进入隔离 CI，暂不用于生产。
