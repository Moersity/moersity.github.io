缓存未命中也要限负载，PD 就绪要看剩余容量

截至 2026-10-24 09:00（Asia/Shanghai）。今日聚焦 SMG 低命中路由、容量就绪与多模态错误边界，同时追踪 MoE padding 正确性、KV 辅助状态和 Kubernetes sandbox 资源约束。除官方公告日期外，下文时间均为北京时间；main 合并不等于稳定版发布，作者与厂商测试不作独立实测结论。

01

今日最重要

  1. SMG：cache-aware 未命中路径补上压力门槛 — #2810 于 10-24 00:04 合并。前缀未命中、event-driven 无重叠 fallback 和 hash 无 holder 等路径接入 count-pressure gate；吞吐评分只计运行中 rank 的 live rate，闲置 worker 使用候选集 nominal rate，无活跃样本才回退默认值。判断：低命中突发也可能把流量挤到单一 worker，不能只用高命中压测验收。KV-pressure fallback 刻意不加此 gate，避免把流量导向 KV 饱和节点；专项测试的 4:4 分流不代表线上所有负载都均衡。
    SMG #2810
  2. SMG：PD readiness 从存活判断扩展到容量门槛 — #4331 于 10-24 01:01 合并，为 P/D 分角色提供最少健康数和健康百分比。门槛取最少数量与向上取整的 expected fleet 百分比中较大者；移除 worker 不会缩小百分比分母，默认仍各一台。判断：容量退化和进程存活需要分开处理。入口负载均衡器必须尊重 readiness 才能摘流；此能力不执行 request shedding，不强制精确 P:D 比，也不是 SLA 保证。
    SMG #4331
  3. vLLM：MoE padding 可能让有效 token 走错专家 — #59717 于 10-24 06:51 合并。无 expert_map 时，moe_permute 的 -1 CUDA graph padding ID 未统一重映射，可能造成 expert_first_token_offset 错误。修复复用已有 invalid-ID remap，并处理空 batch；涉及 CUTLASS FP8 MoE 等调用路径。判断：优先加入相同有效 tokens、不同 padding 与 batch size 的输出不变性测试，而非只跑吞吐。作者 H100/CUDA 13.1 验证不覆盖所有硬件；所有 ID 有效或已有 expert_map 的路径不属本次行为变化。
    vLLM #59717
02

AI 推理 / 系统工程动态

SMG #4330（10-24 01:00）将 image/audio、video fetch timeout 暴露到 router CLI 与 vLLM Rust launcher，flag > env > default；#4355（08:38）把源站 5xx、预算超时、断流映射为 502 server_error，客户端输入错误仍为 400。网关不内部重试这些媒体故障，也不计为 worker breaker 失败。vLLM #62591（06:24）则将 routed-experts 辅助输出 retain/release 与 KV cache events 协调，避免 KV 仍命中、辅助输出却先被独立 LRU 淘汰。

判断：下载预算与推理预算应独立验收，502 不自动等于 engine 故障，也不能改写成统一 504；Python inprocess loader 等路径有例外。缓存正确性还包括 block 关联的辅助状态，需测试外部命中裁剪、淘汰和容量增长告警，不能只核对 KV 字节。

后端与云原生 / Rust / Golang 动态

Kubernetes #141014 于 10-23 15:19 合并，修正部分容器未声明 limits 时，将已声明 limits 的部分和误作 pod sandbox 上限的问题，使其与 pod cgroup 的 unlimited 逻辑对齐。SMG Helm #4286（10-24 05:59）把 router progressDeadlineSeconds 默认设为 1920s，#4364（08:41）将 worker deadline 调整为 startup probe budget + 600s。SGLang #46066（07:47）修复 Rust prefill 端口解析：自带 bootstrap server 的 transfer backend 保留独立端口，CommonKVBootstrapServer 家族仍可复用 API listener。

判断：Kata 等 VM runtime 会使用 sandbox resources，影响不能简单外推到 runc；分别核对容器、Pod cgroup 与 sandbox 三层约束。Helm deadline 只改变 rollout 失败判定，不加速启动，应联查 helm timeout 与 worker startup timeout。Rust 端口修复需验证注册地址和真实 listener，不能只看 health。Go 官方博客检索最新可见仍是昨日已报道的调查公告，本期不重复凑数；这不代表整个 Go 生态没有变化。

值得看的项目 / 论文 / 工具

  1. TensorRT Global Performance Tuner：精度先过滤，性能再排序 — NVIDIA 10-23 发布技术文章，介绍 TensorRT 11.1 的可搜索 build route：trtexec 构建并测量候选，排除构建失败及精度不合格项，再选最快的合格引擎。文章列出的十个 workload 收益为厂商测量，不是通用收益保证。判断：把代表性输入、边界 shape 和质量指标一起固化。模型、GPU、CUDA 或 TensorRT 变化后重新测量；调优缓存帮助续跑，但旧最优路线不能无条件移植。

产业趋势与投资信号

Google Cloud 10-22 公告：新增 Anthropic-managed Claude 选项正式可用，与 Google-managed 选项并行。官方称同模型首日可用、价格一致并通过 Google Cloud 计费；关键区别包括运营与数据处理方、适用条款及 Claude 平台新功能的接入节奏，而非仅模型名称。

判断：采购与架构评估应比较数据处理责任、治理能力及功能上线节奏。不能因模型和价格相同就假设两种路径的 VPC、CMEK、数据驻留等能力自动等同；应逐项核对对应服务约束，不据此推导投资回报。

行动建议

  1. 对 cache-aware 进行低命中突发、闲置转繁忙和不同轮询周期回归，联合观察分流、TTFT 与 KV 压力，不只比较命中率。
  2. 按实际 expected P/D fleet 设置 readiness 容量阈值，注入单角色缩容，验证入口摘流以及恢复行为。
  3. 对 FP8 MoE 增加单请求、小 batch、不同 CUDA graph padding 的输出一致性测试，保留精度基线后再比较性能。
  4. 区分媒体源站失败、客户端输入错误与 engine 失败，核对 400/502/例外路径和客户端重试预算。
  5. 联查 Helm rollout deadline、startup probe 与外部等待超时，并在 Kata/多容器场景核对 sandbox 上限与真实 bootstrap listener。
