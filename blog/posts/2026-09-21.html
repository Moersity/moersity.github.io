多模态处理下沉 Worker，资源边界必须随之下沉

SMG 打通 Media Reference、Worker/Sidecar 处理与过载回退；vLLM 修复空闲 Rank 污染 Draft KV；SGLang 为长前缀传输和 Indexer 临时显存建立硬边界。

01

今日最重要

  1. SMG 将多模态 Fetch 与 Preprocess 从 Router 下沉到 Worker — SMG 合并完整 Media Reference 栈：gRPC Wire Contract 让请求携带按 Prompt 顺序排列的 Image/Video URL；Router 在 auto 模式下仅对已明确 Opt-in、且所有候选 Worker 都声明处理能力的模型转发引用，否则保持原 Router Preprocess 路径。Qwen3-VL 与 Llama 4 首批启用；PD 两腿会收到同一组引用，由 vLLM 原生生成 Hash、Placeholder Expansion 与 M-RoPE Grid。另有 Redis Sidecar Backend，把 URL Fetch 和 HF Processor 从 vLLM API 进程进一步隔离，并用 Model、vLLM Version、Dtype 等构成 Fingerprint，只有 Sidecar 存活且指纹一致时才对外宣告能力。判断：这把 Router 从大 Tensor 搬运节点变成能力协商与路由节点，但一致性约束也转移到了 Worker Fleet：同一模型只要混入不兼容 Worker，auto 就应整体回退；Sidecar 指纹、URL Scheme、PD 双腿能力和 Retry Pin 都必须作为调度约束，而不是运行后才发现。
    SMG Media Reference Wire Contract #2399SMG Router Media Reference Forwarding #2400SMG Redis Media Sidecar #2401
  2. SMG 为多模态请求补齐内存预算、过载转移与可重试故障 — Router 新增可选的 In-flight Preprocessed-media Byte Budget：单请求超过总预算立即返回 413，短暂等待后仍无空间则返回 429；Worker 侧不再让超额请求无界排队，而是在等待数达到可运行并发时返回可重试状态，让 Router 改投其他 Worker。此次还把瞬时 Fetch、Redis Round-trip Timeout、沉默 Sidecar、Caller Cancel 后的 Remote-prefill Block Cleanup，以及 Engine 实际 Per-modality Limit 纳入同一条故障语义。判断：多模态下沉若只有功能路径、没有 Byte Budget 和 Retry Contract，会把 Router OOM 改写成 Worker Queue Collapse。上线时应同时配置 Router Byte Cap、Worker 并发、Sidecar Queue/Timeout，并观测 413、429、Retryable UNAVAILABLE 与跨 Worker 重选；默认关闭的预算不能被误当成已有保护。
    SMG In-flight Media Memory Cap #2585SMG Media Failure and Load Shedding #2596
  3. vLLM 修复空闲 DP Rank 的 Dummy Draft 写坏 Prefix KV — Model Runner V2 在数据并行 Speculative Decode 中，空闲 Rank 的 Dummy Batch 会用过期的 Persistent Block-table Row 计算真实 Slot Mapping，并向上一个占用该 Slot 的请求首 Block 写入 Drafter K/V；这些 Block 可能已进入 Prefix Cache，之后命中会读到被污染的 Draft KV。修复以 idx_mapping=-1 标记 Dummy Row，并在 CUDA Kernel 内直接输出 PAD Slot，避免 Graph Replay 再次写入。提交者在 4×GB200、GLM-5.2、DP4/EP、MTP k=5、FP8 KV 场景复现了 MTP Acceptance 锁死为零，并在修复后记录 66,164 次 Dummy Draft Step 全部写 PAD。判断：这是典型的‘读侧隔离了 Dummy，写侧仍信任持久状态’。任何 CUDA Graph Replay、Padding Row 与 Idle-rank 路径都应以不可写 Slot 为默认值；仅检查输出质量平均值不足以发现污染，应按 Conversation 跟踪 Draft Acceptance、Prefix Block 身份和 Reset-cache 后是否恢复。
    vLLM Spec Decode KV Corruption Fix #56734
  4. SGLang 将 Cached-prefix DCP 传输切分到 Pack Capacity 内 — Prefill 命中很长 Radix Prefix 时，Decode Worker 仍需接收完整 KV；旧 DCP Pack Buffer 只按 Prefill Compute Chunk 定容，超大 Prefix 会退化为逐 Token RDMA。新实现公开按页对齐的 Pack Capacity，把大传输切为多个 Segment，并校验每个 DCP Rank 的 Region Boundary。提交者在 8×B200、Kimi Linear 48B-A3B、NIXL、83K/164K Cached Prefix 下报告 C8 吞吐相对主干提高约 10.9×/16.6×，达到 TP4→TP4 对照的约 95%，同时明确 Mooncake RDMA 未在该开发机跑通。判断：收益来自消除 Size-threshold 后的 Fallback，而不是扩大固定 Buffer。生产验证应区分 NIXL、Mooncake TCP/RDMA，记录 Segment 数、Per-rank Region、Fallback Warning 与 TTFT；不能把单机 NIXL 的近似对照结果外推为所有 Transport 和 DCP8。
    SGLang Bounded DCP Transfer #40376
  5. SGLang 把 DeepSeek-V4.1 Dense Indexer 临时显存压到固定预算 — Dense Prefill Indexer 的 FP32 Score 和候选 Mask 随 Query Token×Visible Context 增长；16K Query、1M Context 的旧路径仅主要临时量就估算为 96 GiB/GPU。新实现以 2 GiB Score Budget 做 Row Tiling，并在层间保存每行最多 2,048 个 Int32 Candidate Block ID，按 Tile 临时重建 Mask。单 B200 微基准中 16K×1M 的额外 PyTorch Peak 从 96.01 GiB 降至 2.72 GiB；4×B200 全模型冷 Prefill 完成到 1,048,448 Token，但 2.72 GiB 不是所有 Shape 的严格总上界。判断：临时 Workspace 必须进入 Admission 与 Capacity Model，不能只看 KV Cache 余量。Row Tiling 与紧凑候选表示给出正确方向，但上线应测 Partial Block、Allocator Fragmentation、不同 Chunk Size 与 Full-model P99，不能把 Score Budget 等同于进程峰值。
    SGLang Dense Prefill Indexer Memory Bound #40217
02

AI 推理 / 系统工程动态

SMG 最近 24–48 小时的实质进展集中在 Worker-side Multimodal：Media Reference、Router Capability Gate、Redis Sidecar、MiniMax M3 多视频与 Image+Video 路径已合并；Proto/Servicer 随后更新到 smg-grpc-proto 0.4.20 与 servicer 0.12.0。多个 Video Clip 已改为并行预处理，提交者在 640×480、每 Clip 8 Frame 的微基准中报告 2/4/8 Clip 分别从 13.6/28.6/54.5 ms 降至 9.6/16.8/35.2 ms。更重要的是后续修复已覆盖 Byte Budget、Queue Shedding、Transient Fetch 与 Redis Timeout。SMG 最新仓库 Release 仍为 v1.10.1；这些主干能力不能仅凭 Release 页面视为已进入稳定版。

判断：SMG 正从 Router-centric Multimodal 迁移到可协商的分布式 Media Pipeline。采用者应锁定 Proto、Servicer、Router 与 vLLM 版本组合，分别压测 In-process 和 Redis Sidecar，验证 PD 两腿 Hash/Grid 一致、取消清理、Sidecar Fingerprint、混合 Worker 回退与 Queue Saturation；性能数字仅来自 PR 微基准，需在真实 Fetch/Decode 占比下复测。

03

后端与云原生 / Rust / Golang 动态

Kueue 修复 Elastic Job Scale-up 卡死：当旧 Workload 只是 Reserved、仍等待 AdmissionCheck 时，Replacement 过去被错误要求必须超过 minCount；若没有额外容量，Job 永远无法先以基线副本启动。修复后只有旧 Workload 已完全 Admitted 时才要求真实增长，否则 Replacement 可先按 minCount Admission，再保留目标 count 供后续扩容。KServe 主干合并 v0.21.0-rc1 准备 PR，包含 Starlette Form Parsing DoS 缓解、pytest 依赖修复和 controller-runtime v0.24.1，但截至核验时 GitHub Release 列表仍只有 v0.21.0-rc0，不能写成 rc1 已发布。最近 24–48 小时未见 Go、Rust 或 Kubernetes 新稳定版本。

判断：批调度控制器必须区分 Reserved、Admitted 与 Running，不能用‘存在被替换对象’代替状态机。对 KServe 则应区分 Release-preparation Merge 与可下载 Artifact；生产升级只根据已发布 Tag/镜像及其 SBOM，而不是主干版本号。

值得看的项目 / 论文 / 工具

  1. SMG Media Reference 四层迁移样板 — #2399/#2400/#2401 把协议、Worker Processor、Router Capability Selection 与 Redis Sidecar 拆成可独立审查的层，并为不支持的模型保留字节一致的旧路径。判断：适合作为把 CPU-heavy Preprocess 从 Gateway 下沉到 Worker 的设计参考，重点学习 Capability Advertisement、Fleet-wide Gate、Retry Pin 和 Fingerprint，而不是只复制 Sidecar。
    SMG Media Reference Stack
  2. SGLang Cached-prefix PD Benchmark Client — #40376 附带独立 Cached-prefix TTFT Benchmark，区分 Warm Prefix、Unique Suffix、Concurrency、Transport 与 DCP/TP 对照，并保留每个响应、Cache-hit 与 TTFT。判断：可借鉴其矩阵测试 PD 传输阈值；务必加入真实 RDMA、不同 Page Size、DCP8、失败回退与 P95/P99，而不是只保留算术均值。
    SGLang DCP Transfer Benchmark #40376
  3. vLLM 多模态展开后的 Token Bound — vLLM 修复 truncate_prompt_tokens 在 Placeholder Expansion 前生效、导致 Qwen3-ASR 请求 96 Token 却返回 147 Token Prompt 的问题；新路径在展开后重新检查上限，并拒绝切断 Multimodal Span。判断：这是 Prompt Budget 的实用测试模板：限制必须作用于最终送入 Engine 的 Token Sequence，并验证 Left Truncation、Span Offset、完整丢弃与跨 Span Cut。
    vLLM Post-expansion Prompt Bound #57076
05

产业趋势与投资信号

最近 24–48 小时未核验到足够重大、且有公司一手公告支持的推理基础设施融资或并购，不用二手传闻补位。更明确的工程信号是，多模态 Serving 的竞争点正在从‘是否支持图片/视频’转向‘预处理放在哪里、如何做能力协商、内存和队列是否有界、PD 两腿是否共享正确身份’，而 Spec Decode 与 Prefix Cache 也越来越要求把 Dummy/Padding 写路径纳入一致性设计。

判断：采购或评估推理平台时，应把 Worker-side Media Processing、Sidecar Fingerprint、Fleet Capability Gate、Byte/Queue Budget、Retry Semantics、Prefix KV Write Isolation 和 Long-context Workspace Bound 纳入验收清单；只比较模型覆盖率与短 Prompt Tokens/s 已无法反映生产风险。

06

行动建议

  1. 为 SMG 建立 Router/Worker/Sidecar 兼容矩阵：锁定 Proto、Servicer、vLLM 与模型 Processor 版本，验证 auto/router/worker 三种模式和混合 Worker Fleet 的回退行为。
  2. 给多模态链路同时设置 Router In-flight Byte Budget、Worker 并发与 Sidecar Queue/Timeout；以大视频突发压测 413、429、UNAVAILABLE、跨 Worker Retry 和 Caller Cancel 后资源释放。
  3. 在 PD 场景对同一 Media Reference 比较 Prefill/Decode 两腿的 Placeholder、Hash、M-RoPE Grid 与 Token Count；Sidecar 重启或指纹变化时确认 Worker 立即停止宣告能力。
  4. 升级 vLLM #56734 后，用 Idle DP Rank、CUDA Graph Replay、MTP 与 Prefix Cache 组合回归；按会话监控 p0/Acceptance，并检查 Dummy Slot Mapping 全为 PAD。
  5. 用 83K、164K 及更长 Cached Prefix 压测 SGLang DCP Transfer，记录 Segment 数、Pack Fallback、Per-rank Region、TTFT P99，并分别覆盖 NIXL 与目标 Mooncake RDMA 环境。
  6. 将 Indexer Score、Mask、Media Tensor 和 Transfer Pack Buffer 纳入统一临时内存台账；用长上下文与 Partial Block 压测验证预算外仍有 Allocator/Graph Headroom。
