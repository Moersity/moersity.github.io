预热成功要看真正执行，路由选定的 rank 要真正落地

截至 2026-10-25 09:00（Asia/Shanghai）。本期聚焦 SMG 的预热验收、rank 路由与请求级故障隔离，并追踪 AMD collective、推测解码和小内存端侧模型。除官方公告日期外，时间均为北京时间；合并到 main 不等于稳定版已发布，作者测试与厂商指标不视为独立实测。

01

今日最重要

  1. SMG：预热收到 abort，不能算 shape 已覆盖 — #4434 于 10-25 08:23 合并，将 abort/error finish，以及 INVALID_ARGUMENT、RESOURCE_EXHAUSTED 拒绝状态计为 UnservedRequest；此前 gRPC 调用正常返回也可能被算作覆盖。已有成功 step 后，连续被拒绝的 shape 不再提前终止后续预热；从首个请求就全部拒绝仍在三个 step 后停止。判断：上线门槛应检查 served shapes 和失败原因，不能只看 RPC OK 或耗时。此修复改变预热统计，不改变客户端收到的业务状态，也不证明所有 CUDA graph/JIT shape 都已覆盖。
    SMG #4434
  2. SMG：Rust SGLang servicer 不再丢弃 Router 的 rank pin — #4414 于 10-25 08:23 合并。data_parallel_rank 增加显式 presence，区分 rank 0 和未指定；routed_dp_rank 传入 scheduler 请求并决定对应 socket。多 rank 的越界 pin 在提交前拒绝，单 rank 引擎按前端规则忽略 pin。判断：缓存亲和性要验证实际执行 rank，而非只看网关选中了谁。该 PR 不修改 Python servicer；多 scheduler rank 的 PD leg 尚需后续 #4460/#4461，截点仍未合并，不应将普通 DP 修复外推为完整 PD 支持。
    SMG #4414SMG #4460SMG #4461
  3. SMG：模型输出解析 panic 收敛为单请求错误 — #4135 于 10-25 08:27 合并，对 chat/messages 的流式和整包读取做请求边界隔离。流式 chat 返回 reader_panicked 错误事件后发 [DONE]，非流式返回 500；Messages 流按其协议返回 error 事件。新增 panicked 计数，错误日志带请求归属。判断：客户端应解析流内错误，不能把已有 HTTP 200 或 [DONE] 当业务成功。该错误不归咎 worker、不开 breaker；结构化 panic 消息会脱敏截断，但原 panic hook 仍输出 stderr，日志治理不能只检查新字段。
    SMG #4135
02

AI 推理 / 系统工程动态

SMG #4440（10-25 08:23）修正 KV replay 指标：replay_requested 只记 gap 发现，missed_batches 仅在最终 unrecovered 时累加，避免成功重放仍算丢失或失败重复计数。#4405（10-25 01:51）让 Rust SGLang servicer 传递图像 tensors 与 processor output；#4413（04:06）补充 EPD language-only 的 encoder dispatch，失败通知发往请求所属 rank，图像引用之外的视频/音频引用仍拒绝。已检查近期 PR、合并、Release 与重要 Issue；最新 Release 仍为 10-16 北京时间的 v1.13.0。

判断：KV gap 告警应区分暂时缺口与不可恢复丢失，不能把计数降低当路由质量自然改善。多模态迁移需比较实际 tensor/layout 与输出；#4191 的 10-24 nightly triage 仍报告 vLLM/Mooncake 多拓扑失败，并将其归于 runner 显存争用，这是项目排查记录而非本日报独立根因证明。

后端与云原生 / Rust / Golang 动态

值得看的项目 / 论文 / 工具

SMG PreparedTools：缓存工具 schema 的渲染值，而非每次重建 — #4427 于 10-25 08:24 合并，按工具集序列化字节复用模板值。大于 64 KiB 的序列化工具集直接按请求处理；保留表限制单项估重 1 MiB、总估重 16 MiB 和 64 个工具集，下一项将超过总量或数量限制时重置。命中仍比较字节，chat 与 Messages 共用。判断：适合固定工具集、多轮消息的工作负载。作者 mock 测试中 allocation calls 减少约 25.6%，不能当 GPU 端到端吞吐增益；估算权重也不是 RSS 硬上限，需压测工具集 churn、巨型 enum 和未命中成本。
    SMG #4427
  2. SGLang AMD collective 与 vLLM draft budget：先守住规模边界 — SGLang #34543（10-25 06:36）将超过 16 MiB 工作缓冲的 deterministic all-reduce 改为复用缓冲分块，修复大输入错误归约与注册表耗尽。vLLM #58466（04:35）让 batch-sharded sampling 在 draft budget 受限时读取实际 admitted draft counts，避免 host 上界与 GPU 实际数不一致。判断：前者验收应覆盖缓冲边界和长时重复归约，不能把错误旧实现当性能基线；后者用 host 等待换取准确分片，需联合测峰值 logits 显存、低并发延迟和 CPU run-ahead。两项作者硬件测试均不保证所有模型/硬件相同表现。

行动建议

  1. 把预热验收从 RPC 成功改为实际 covered/failed shapes，注入 abort 与 admission refusal，确认后续有效步骤仍执行。
  2. 对 cache-aware + DP 记录选中 rank 和 scheduler 实际执行 rank，覆盖 rank 0、未指定、越界，以及 Python/Rust servicer 差异。
  3. 用故障输出测试流内 reader_panicked、Messages error 与非流式 500，检查客户端状态机及 stderr 是否泄露模型内容。
  4. KV event 告警分别统计 replay requested 与 unrecovered batches；多模态升级分别验证 tensor 路径、EPD 引用路径和失败清理。
  5. 对 GPU collective 与 speculative decoding 先做边界尺寸和输出一致性回归，再比较吞吐与同步开销。
