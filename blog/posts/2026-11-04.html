SMG 1.14 转正需核对升级顺序，异步 KV 预取仍要限制占用

SMG 正式版与后续主线分开验收；vLLM 将 KV 传输与运行槽位解耦，SGLang 合并写回等待，Kubernetes 修正同名节点重建的存储所有权。事实以近 24–48 小时一手材料为主，测试收益保留适用范围。

01

今日最重要

  1. SMG 1.14.0 转正：升级重点是兼容性与滚动顺序 — SMG v1.14.0 于 11 月 3 日 19:49 UTC 正式发布。Symphony 成为默认 parser，Rust servicer 可用于各引擎但 Python 仍为默认；旧 KV index 选项与 per-policy load_check_interval_secs 被移除或拒绝。新 servicer 在 SERVING 前预热，发布说明要求先 gateway、后 engine pods，配套 smg-grpc-servicer 0.15.0。gateway API key 不再转发上游，worker/provider 需注册 api_key。判断：把本次升级当作配置、探针与回滚方案变更：上线前扫描废弃参数，检查 startupProbe 与 rollout deadline；保留 --parser legacy 回退路径。 发布性能数字有特定负载边界，不外推为所有部署的容量提升。
    SMG 1.14.0 转正：升级重点是兼容性与滚动顺序
  2. vLLM：满 batch 也能提前启动有上限的异步 KV 加载 — #65319 于 11 月 3 日 23:47 UTC 合并。新增可选 --max-num-inflight-kv-loads，默认 None 保持旧行为；上限同时计入正在加载及已完成但尚未获运行槽位的请求。独立队列允许 batch 满或 token budget 耗尽时预取，connector 通过 may_load_async 选择是否适用。作者较大测试集报告 1084 通过、9 失败，尚待确认是否基线失败；端到端 P/D benchmark 未完成。判断：这是把传输和运行槽位解耦的调度机制，不是已证实的吞吐收益。按槽位释放率与传输延迟调上限，并计量额外 KV 占用和首轮加载突发。
    vLLM：满 batch 也能提前启动有上限的异步 KV 加载
  3. SGLang：HiCache write_back 每轮淘汰合并等待 — #46930 于 11 月 3 日 19:56 UTC 合并，将每个 victim 分别提交和等待改为整轮排队、共同提交、等待一次，再按原顺序降级，不改变 victim 选择。作者单 GB300、gpt-oss-20b 淘汰受限场景五轮交错测试吞吐 113.0→120.5 req/s（+6.6%），TTFT p99 813→559 ms，命中率仍 0.874；Qwen3-8B +3.1% 被作者标为噪声范围，无淘汰场景基本中性。判断：收益取决于每轮淘汰数量和写回压力，首个拷贝仍需等在途 forward。要区分减少等待与增加缓存命中，不能泛化为所有 HiCache 配置提速。
    SGLang：HiCache write_back 每轮淘汰合并等待
02

AI 推理 / 系统工程动态

已检查 SMG 近期 PR、合并、重要 Issue 和 Releases。正式版之后，#4971 于 11 月 4 日 01:01 UTC 合并，让所有 gRPC worker 建立订阅：cache-aware 使用 Events，其他需要负载的策略使用 Loads；数据新鲜时跳过 GetLoads，失活或不支持时回退轮询。作者 CPU mock DP4 三轮交错测试中 least_load 的 rank in-flight max/min 中位数 1.24→1.02、吞吐 57.6→60.8 req/s，但 TTFT p50 40→44 ms，真实四 rank 引擎仍待验证。#4837 于 11 月 3 日 23:56 UTC 合并，将 GET /v1/models 的 caller credential fanout 按 API family 匹配；多个同 family 厂商仍可能收到同一 key。两者均为发布后主线，不声称已包含在 v1.14.0。

判断：负载流验收须覆盖 rank 新鲜度、中断与旧 servicer 回退；凭据边界须按实际上游信任关系检查，API family 过滤不等于逐厂商隔离。

SMG #4971：非 cache-aware 策略也接入 gRPC load streamSMG #4837：BYOK 模型列表按 API family 限定凭据广播
03

后端与云原生 / Rust / Golang 动态

#143727 于 11 月 3 日 19:37 UTC 合并，修复 kubelet 启动时缓存前一代 Node UID、反复创建错误 owner 的 CSINode 并被 GC 删除的问题。CreateCSINode 读实时 UID，驱动安装时更新缓存，ownership mismatch 再取实时 UID 后决定是否删除。PR 明确为 1.35 引入的回归；作者 Go -race 单测与 live cluster 同名替换、GC 存活、CSI attach/mount 验证通过，未证明已进入各发行补丁版。 Rust/Python 协同方面，SMG #4944 于 11 月 3 日 16:14 UTC 合并，为 SGLang 交错图像/视频携带分模态批次、顺序和绝对 prompt offset。混合请求需 gateway、servicer、proto 联动升级；旧 stub 的文本/单模态兼容不代表混合兼容。作者报告 scoped Rust/Python 与 ffmpeg 测试通过，未跑 GPU 模型质量测试。

判断：节点重建需按对象 UID 而非名称处理所有权。验证存储恢复时应联合观察 Node、CSINode ownerReferences 与 GC，避免将注册循环只归因于驱动故障。 多模态验收还需核对跨语言协议、PD 传递和失败清理，不能只看单侧编译通过。

Kubernetes：同名 Node 重建不应沿用旧 UID 注册 CSINodeSMG #4944：SGLang 支持交错图像与视频的多模态批次

值得看的项目 / 论文 / 工具

  1. HiSparse：异常出口先归还附属状态，再释放 KV — #43911 于 11 月 4 日 00:54 UTC 合并，为 PD decode checksum mismatch 和 chunked prefill abort 两处出口补 request_finished，先回收 host/device 或 scratch 行再释放 KV。仅 enable_hisparse 生效。作者列出 H200 PD、B200 speculative 与 5090 单测通过，但 checksum H100 测试仍排队，服务器端完整泄漏复现进行中；不能宣称全矩阵验证完成。判断：异常退出回收要覆盖 KV 之外的辅助池，并验证回收顺序；正常完成路径通过不足以排除长期泄漏。
    HiSparse：异常出口先归还附属状态，再释放 KV

产业趋势与投资信号

AMD 11 月 3 日发布 2026 Q3 财报：总营收约 134 亿美元，同比增长 45%；Data Center 营收 85 亿美元，同比增长 97%，公司归因于 EPYC 需求与 Instinct MI450 系列 GPU 上市。属于厂商财务披露，数据中心口径同时包含 CPU 和 GPU，不能全部等同于推理需求或归因于某一产品。

判断：产业信号显示计算需求覆盖主机和加速器；工程采购仍以实际模型、ROCm 兼容、交付与单位有效 token 成本评估，收入增长不是服务性能或投资收益保证。

06

行动建议

  1. 升级 SMG 1.14.0 前扫描移除参数，按 gateway 先于 engine 的顺序准备 rollout；核对上游 api_key、预热 readiness 和 legacy parser 回退。
  2. 试验异步 KV 预取时同时计量加载中与已完成待运行请求的块占用，按槽位释放率和传输延迟扫上限，不把功能合并当作吞吐验证。
  3. HiCache write_back 压测分开测淘汰受限与无淘汰场景，保持命中率、victim 顺序和在途 forward 等待条件一致。
  4. 节点同名重建时检查 Node UID、CSINode ownerReferences 和 GC；混合图像/视频请求同时验证 gateway、servicer、proto 与 GPU 质量。
  5. 验收 load stream 的失活回退和 DP rank 新鲜度，审查同 API family 多厂商的凭据发送目标；把后续主线修复与正式版明确区分。
