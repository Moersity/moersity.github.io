SGLang 0.5.18 升级栈底，确定性与冷启动必须重新验收

SGLang 更新 Torch、Triton、FlashInfer、缓存目录与多项默认行为；Kubernetes 发布稳定补丁和 1.37 rc.1，Rust 1.98 又显式引入可重排但非确定性的浮点 API。

01

今日最重要

  1. SGLang v0.5.18 发布，依赖栈与默认行为大幅变化 — 版本升级到 Torch 2.13.0、Triton 3.7.1、FlashInfer 0.6.17 和 sgl-kernel 0.4.6.post1；所有编译 Kernel 缓存默认迁入 SGLANG_CACHE_DIR，DeepEP 改用发布 Wheel，torchao 集成被移除。判断：这不是可直接滚动替换的小补丁；镜像、AOT Kernel、缓存预热、量化与回滚路径都要重新验证。
    SGLang v0.5.18
  2. SGLang 同时强化冷启动、确定性和推测解码正确性 — Checkpoint 页面可与 CUDA Graph 捕获重叠，官方在 Qwen3-32B/H100 上报告相对默认路径启动加速 2.38 倍；版本还修复 Draft Token 超过 4 时的静默 KV 损坏、TP>1 确定性 All-reduce 等问题。判断：吞吐优化之外，静默错误与启动恢复时间已成为生产推理的一级指标；升级验收必须包含逐 Token 一致性和崩溃恢复。
    SGLang v0.5.18 Release Notes
  3. Kubernetes 发布 1.36.4、1.35.8、1.34.11 与 1.37 rc.1 — 三个受支持稳定分支同步获得补丁版本；1.37 rc.1 仍明确标记为预发布。判断：生产集群优先评估所在稳定分支补丁，1.37 rc.1 只用于 Device Plugin、Kueue、Gateway、CNI/CSI 和 RDMA 兼容测试。
    Kubernetes v1.36.4Kubernetes v1.35.8Kubernetes v1.37.0-rc.1
  4. Rust 1.98.0 增加 Algebraic 浮点方法 — f32/f64 新增允许编译器利用实数代数性质重排加减乘除和余数的方法，可帮助向量化，但官方明确这些方法是非确定性的；同时新增低开销整数 format_into。判断：推理前端可关注格式化收益，但可复现评测、采样和数值控制路径不应无审查地采用 Algebraic 浮点 API。
    Rust 1.98.0 公告
  5. Prefix 路由与 Agent 工具缓存出现可落地新方案 — CacheRoute 用周期性计划平衡 Prefix Affinity 与负载，论文在 60 张 H100 上报告命中率从 64.1% 提至 93.2%；ReCache 则把工具/技能 Schema 做成组合无关的独立 KV 块。判断：缓存命中率不能脱离负载偏斜与语义准确率单独优化；两种方案都应先做 Shadow Replay。
    CacheRouteReCache
02

AI 推理 / 系统工程动态

SGLang 0.5.18 把工程重心同时推进到启动、正确性与缓存可观测性：Checkpoint Staging 可和 CUDA Graph 捕获重叠，KV Event 增加 Cache Salt 与合并，确定性测试覆盖 TP All-reduce、MTP 与 HiCache；与此同时，Torch/Triton/FlashInfer 与缓存目录变化会让旧镜像、预热卷和 AOT Kernel 假设失效。CacheRoute 与 ReCache 则说明 Prefix 复用正在从被动命中走向计划分配和资源级组合。

判断：升级前先固定完整依赖与缓存工件，再用同一 Trace 测启动、首请求、稳态、逐 Token 正确性和故障恢复；缓存优化必须同时报告命中、偏斜、迁移与重算成本。

03

后端与云原生 / Rust / Golang 动态

Kubernetes 为 1.36、1.35 和 1.34 发布新补丁，1.37 rc.1 仍只适合预演。Rust 1.98.0 的 Algebraic 浮点方法允许优化器重排并明确不保证确定性；format_into 则为整数格式化提供低动态分派路径。SGLang Rust Server 也新增 Qwen VL 原生多模态处理，继续把请求入口从 Python 热路径迁出。

判断：控制面应先升级受支持稳定补丁；Rust 性能 API 要按语义分区使用——请求解析、指标格式化可以试，影响数值一致性的路径必须保持严格运算。

04

值得看的项目 / 论文 / 工具

  1. SGLang v0.5.18 Release Notes — 集中列出依赖升级、缓存目录迁移、默认行为、已知问题、启动优化和正确性修复。判断：今天第一优先级阅读；先看 Breaking Changes 与 Known Issues，再看性能数字。
    GitHub Release
  2. CacheRoute — 以周期性计划给高频 Prefix 分配稳定 Warm Set，并显式处理热点与负载。判断：论文主动给出无收益反例，适合直接复用其 Shadow Replay 决策门槛。
    arXiv
  3. ReCache — 通过资源局部位置、选择性层/Head 路径及结构语义裁剪，复用不同排列组合的工具 Schema。判断：适合 Agent 平台验证工具定义占比、调用准确率与 KV 显存曲线。
    论文代码
  4. Kubernetes Lazy Pull 模型交付研究 — 研究发现懒拉取使冷启动与镜像大小解耦，却把成本推迟到读取阶段，并可能在节点缓存耗尽时让 Running Pod 持续读失败。判断：使用 eStargz 或 SOCI 的模型平台应立即检查 Snapshotter 缓存容量、磁盘告警与真实文件读取探针。
    论文实验工件
  5. Rust 1.98.0 — 重点包含 Algebraic 浮点方法、NumBuffer 与整数 format_into，以及新增稳定 API。判断：升级前应为数值敏感路径添加 Clippy/Code Review 规则，避免误用非确定性方法。
    Rust 官方公告
05

产业趋势与投资信号

最近 24–48 小时未核验到足够重大且有一手公告支持的推理基础设施融资或并购。更明确的产业信号来自交付层：SGLang 在同一版本覆盖新模型、Rust 多模态入口、Blackwell 通信、启动恢复、确定性和分层缓存；同时，Prefix 计划路由与 Agent Schema 缓存把降本空间推向更上层的工作负载结构。

判断：推理平台的竞争正在从单次 Kernel 峰值转向版本治理、缓存资产化、恢复时间和正确性证据；能持续证明这些指标的团队更容易获得企业预算。

06

行动建议

  1. 为 SGLang 0.5.18 建立独立候选镜像，锁定 Torch 2.13、Triton 3.7.1、FlashInfer 0.6.17 与 AOT Kernel，不复用旧缓存假设。
  2. 迁移或重新预热 SGLANG_CACHE_DIR，分别测空缓存、预热缓存、首次启动和崩溃后重启时间。
  3. 对推测解码执行逐 Token 一致性测试，覆盖 Draft Token 大于 4、TP>1、DP Attention、MTP 与 HiCache。
  4. 在隔离集群验证 Kubernetes 稳定补丁；1.37 rc.1 仅做 GPU、Kueue、Gateway、RDMA/CNI/CSI 兼容性测试。
  5. Rust 1.98 升级审查 Algebraic 浮点调用；对 CacheRoute、ReCache 和 Lazy Pull 先做 Shadow Replay、文件读取探针与容量压力测试。
