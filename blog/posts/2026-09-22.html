下沉多模态之后，先守住缓存身份与能力边界

SMG 扩展 MiniMax-M3 Worker 侧处理并改进逐图像复用；vLLM 修复多模态接收缓存的陈旧 Tensor；SGLang 将分层 KV 缓存覆盖混合模型。

01

今日最重要

  1. SMG 允许 MiniMax-M3 在 vLLM Worker 侧展开媒体锚点 — MiniMax-M3 的图片、视频各用一个与引擎展开位置相同的锚点 Token，SMG 因而将该模型加入可转发 Media Reference 的集合。只有操作员开启 Worker 侧处理、全体 Worker 宣告能力且请求没有逐项尺寸提示时才走新路径；其余仍由 Router 预处理。提交者用真实引擎核对锚点，但未运行需要 GPU 的完整 Worker-mode 多模态端到端测试。判断：这是昨天 Media Reference 栈的实质扩展，不等于两条路径已语义等价：上游引擎对部分 MiniMax 图像的定容与 Router 不同，回答可能变化。需要完全一致的服务应继续关闭该模型的 Worker 侧模式，直到定容与端到端结果对齐。
    SMG PR #2609
  2. SMG 对小批量图片做逐项缓存，并隔离缓存身份 — 启用 SMG_MM_PIXEL_CACHE_MB 后，小于 32 张图片的请求可按图片去重、并行处理未命中项，再按原顺序还原；即便结果超过缓存预算，请求内重复项仍可复用。本次仅对明确保证逐图像处理独立的 Qwen2/2.5-VL 和 Qwen3-VL Processor 启用，其他模型及大批量请求继续走整批路径。缓存指纹纳入模型、模型配置、Tokenizer 与预处理配置。判断：逐项缓存的收益来自重复媒体，但它改变了 Batch 边界；只有能证明逐项与整批输出逐位一致的 Processor 才应启用。上线时同时检查跨模型污染、配置变更后的冷缓存、乱序完成重组以及零缓存容量下的请求内去重。
    SMG PR #2602
  3. vLLM 修复接收端多模态缓存把旧 Tensor 当作新 Payload — Frontend 与 EngineCore 的独立 LRU 淘汰可能发生漂移：Frontend 重新发送完整媒体 Payload 时，Engine 过去仍把同一 Hash 的旧缓存项视为权威，导致新 Placeholder 布局配上旧 Tensor，Embedding Merge 可直接杀死 EngineCore。修复为只要收到完整 Tensor，就替换接收端旧项并返回新 Payload；仅 Hash、无数据的 Cache-only 查询语义保持不变。判断：Hash 命中不能覆盖显式传来的数据。多进程缓存协议应把完整 Payload 视为刷新依据，并测试两端独立淘汰、同一身份不同 Shape、随后仅 Hash 再取以及 Engine 不崩溃。
    vLLM PR #57833
  4. SGLang 将 HiCache 覆盖到 GDN、SWA、三池和 MLA 混合布局 — 新的 Unified-memory 分层缓存路径在 Host Transfer 时把虚拟 KV ID 解析到各层真实 Buffer Index，并在传输完成前禁止 Device-page Relocation；SWA 恢复使用精确的 Full-attention 虚拟 ID，Mamba State 通过连续 Staging Buffer 搬运。提交者报告 567 项单测与 8 项 H200 端到端测试通过，端到端场景确认了真实 Host Hit，并比较生成文本与 Logprob。判断：混合模型的分层缓存不是简单复制页：必须证明虚拟 ID、层内布局、传输完成事件、Compact 后索引与回滚一致。采用时应按 GDN、SWA、MLA、三池和 DCP 组合分开验收，不把单一模型的 Host-hit 测试外推到所有池形状。
    SGLang PR #37507
02

AI 推理 / 系统工程动态

SMG 最近 24–48 小时还把 Kubernetes Worker Reconciliation 与 Mesh-router Peer Discovery 拆成独立任务、配置和生命周期，为未来 File/Slurm/Consul Worker Provider 铺路；本次没有引入新 Provider。它同时修复 IPv6 地址拼接、无效 Mesh Port 提示以及启动失败后 Watcher 遗留。该 PR 带有 Rust Public API 破坏性变更，Python、Go、CLI 与序列化配置不受影响；仓库最新正式 Release 仍为 v1.10.1。视频长片段选帧也修复了 ffmpeg 列表表达式超过 100 项后静默退回普通采样的问题。最近的重要 Issue #2380 仍开放：超长 Prompt 可能返回 500 而不是 400，对应修复 PR #2618 尚未合并。

判断：SMG 今天的主线是迁移边界的显式化：多模态模式要管模型/Worker 能力，服务发现要管 Watcher 所有权，发布还要管 Rust SemVer。不能把开放的超长 Prompt 修复或新 Provider 当成已交付；下一次正式发版尤其应检查 breaking API 的版本号和迁移说明。

03

后端与云原生 / Rust / Golang 动态

Kueue 合并默认关闭的 Alpha FairSharingRefill：ClusterQueue 在一个调度周期中 Admission 了首个 Workload 后，可让同队列下一个 Workload 在重新计算的 Fair Sharing 顺序中竞争，但受每周期预算和 Direct Fit 限制。提交者的集中积压基准从 32 个周期降到 4 个，墙钟时间约降 24%，不能外推到所有负载。KServe 只合并了 KernelCache 配置解析、默认值、校验及 Helm/Kustomize 示例，Controller 尚未接线，默认仍关闭。Kubernetes 的 PodGroup Preemption 代码开放自定义 Victim 排序和执行接口，主要服务于 Scheduler-library/Kueue 集成；本次意图保持原调度行为。Go、Rust 最近未见需占据头条的新稳定发布。

判断：调度栈的变化要区分 Gate、配置契约与真正启用的行为。Kueue Refill 可在有公平共享且长期积压的集群试验，跟踪每周期工作量和尾部等待；KServe KernelCache 暂不能列入已可用能力，Kubernetes Preemption 扩展也需单独回归 Victim 顺序。

04

值得看的项目 / 论文 / 工具

  1. vLLM 首个 KV Hints 请求封装 — vLLM 在 Python、Rust、AsyncLLM、EngineCore 与公开 HTTP/gRPC 请求之间加入类型化 KvHintsEnvelope，并保持 MessagePack 线协议兼容；它只建立入口和传递链，尚未定义或执行具体 KV Action。判断：值得跟踪其后续 KV Manager 与策略实现，但现在不能把 Hints 当成可用的驱逐、预热或迁移命令。
    vLLM PR #53423
  2. SGLang EAGLE/MTP Draft Attention 的 Sink+Window 方案 — 新实现让 Built-in EAGLE/MTP Draft 只读取首部 Sink 和最近 Window，Target 仍做完整 Attention；默认 Window 为 0，原路径不变。提交者在单 B200、Qwen3.6-35B-A3B、32K–256K Context 的测试中观察 Triton Draft TPOT 改善，FlashInfer 的 64K 点则基本持平。判断：适合作为长上下文 Spec Decode 的读带宽实验，但 Acceptance 与质量必须同测，不能只看 Draft Kernel 的单步速度；目前未实现论文中的 Ring-buffer KV 回收。
    SGLang PR #32673
05

产业趋势与投资信号

最近 24–48 小时未核验到足够重大、且有公司一手公告支持的推理基础设施融资或并购，不用传闻凑数。工程侧信号更清楚：Media Processor、跨进程 Payload Cache、分层 KV 和公平调度都在从隐式假设转向显式身份、容量及生命周期契约。

判断：评估推理平台时应问四件事：模型/Processor 版本变化能否隔离缓存，显式 Payload 能否压过旧缓存，Host KV 转移是否按真实层布局验证，调度新特性是否有可关闭的 Gate 与可复现的收益。

行动建议

  1. 对 MiniMax-M3 同一组图片、视频分别运行 SMG Router 与 Worker 模式，比较 Token Count、Frame/图像定容、回答与 PD 两腿缓存身份；未对齐前不要做无提示切换。
  2. 在 SMG 逐图像缓存中回放小批量重复图、跨模型同 URL、预处理参数变化、乱序完成和大于等于 32 张图片请求，确认指纹隔离与回退路径。
  3. 针对 vLLM 多模态 IPC 缓存做 Frontend/Engine 独立淘汰测试：同一 Hash 重送不同 Shape 的完整 Payload，随后仅用 Hash 查询，确认不复活旧 Tensor。
  4. 验证 SGLang HiCache 在 GDN、SWA、MLA 与三池布局下的真实 Host Hit、Logprob、搬运中取消与 Compact 后索引；记录池容量和失败回滚。
  5. 在非生产 Kueue 集群开启 FairSharingRefill，比较集中积压下的调度周期、每周期 CPU 时间、队列公平性与等待尾延迟；未评估前保持默认关闭。
  6. 跟踪 SMG 下一正式版的 Rust Breaking API 版本号、Discovery 迁移说明及超长 Prompt 的 400/500 修复；不要把尚未合并的 PR 视为现成能力。
