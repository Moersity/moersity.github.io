长时运行的隐形杀手：Rank 分叉、JIT 专用化膨胀与错误内存计费

SGLang 连续修复张量并行超时分叉、动态 Stride 导致的 Triton 模块累积和 Unified-KV 过度预留；vLLM 则补齐推测解码 Offload 的命中边界。

01

今日最重要

  1. SGLang 将请求超时改为单 Rank 判定、全 Rank 广播执行 — 此前每个 TP Rank 独立扫描墙钟，亚毫秒级时钟偏差可让等待队列在超时边界处分叉，随后不同 Rank 进入 Extend 与 Decode 的不同 Collective 并挂死。新路径只由拉取请求的 Rank 生成 AbortReq，再沿既有请求广播在同一调度轮次执行；提交给出的饱和长上下文验证在修复后连续 21.6 小时未再出现挂死。判断：分布式控制决定不能以各 Rank 的本地时间或本地副作用为真相；Timeout、Cancel、Admission 和 Cleanup 都应由一个权威 Rank 决策，并复用已有有序广播。
    SGLang PR #37143
  2. SGLang 阻断 DSA Prefill 按 Page-table Stride 无界生成 Triton Cubin — EAGLE 扩展后的连续 Page Table，其行 Stride 随上下文长度变化；把该值声明为 tl.constexpr 会让长时运行的 Prefill Worker 持续编译并加载新 CUDA Module，最终在 load_binary 阶段 OOM。修复将 Stride 改为运行时参数并加入 do_not_specialize，测试验证多个上下文长度不再增加专用内核数量。判断：线上 JIT 缓存必须有基数预算。凡是来自长度、Stride、租户或请求内容的整数参数，除非取值域可证明有界，否则不应参与 Kernel Specialization Key。
    SGLang PR #37093
  3. SGLang 纠正 Unified-KV 的 SWA/C4 计费，单 DP Worker Token 容量提升 83.55% — DSv4 Unified-KV 运行时把 SWA 与 C4 State 作为每请求 Ring，但 Pool Sizer 仍按 Token 扩张预留，导致保守扣减大量永不会分配的显存。修复统一 Sizer、Pool、Allocator、Scheduler 与 C4 Addressing 的 Request-slot 语义；PR 报告容量由 6,848,000 提至 12,569,600，并在 8×MI355X、并发 512 下未观察到吞吐、TTFT 或 TPOT 回退。判断：内存模型必须和地址模型、准入计费共用同一个资源单位。按请求的 Ring 不能在容量规划中按 Token 收费，否则优化只是把显存变成不可用的账面余额。
    SGLang PR #38192
  4. vLLM 修复 MTP/EAGLE 下 Offload 已存储却返回零命中的三段链路 — 共享 Group 的 MTP 模型可能被错误地把所有 Group 当成 Drafter；移除易失 Tail 时未对非 SWA Group 扩大查询边界，又会把兄弟 Group 的确认边界压到粗粒度 Chunk 以下；完成请求还可能永久漏存最后一个完整 Drafter Chunk。三项缺陷叠加会让 CPU Tier 已有 KV，却向调度器报告零可复用 Token。判断：Offload 的 Store、Lookup 与跨 Group 对齐是一个协议，不能分别靠局部启发式修补；推测解码还必须把目标验证边界、Drafter 易失尾部和 Chunk 粒度同时纳入测试矩阵。
    vLLM PR #52771
  5. Kueue 修通弹性 Workload 部分扩容的 minCount 全链路 — KEP-12100 Partial Scale-up 生成的 Workload 过去要么被 Validating Webhook 拒绝，要么被 Mutating Webhook 或 Reconciler 清除 minCount，令功能端到端不可用。修复统一采用 MinCountsUsable 谓词，并先写入 Elastic Annotation 再做清理，使 RayCluster 的多 Worker Group 部分扩容能够保留最小副本约束并被调度。判断：准入、默认化、协调与调度必须共享同一能力判定；只修其中一层，会把显式失败变成静默降级，后者对弹性训练和推理队列更危险。
    Kueue PR #15250
02

AI 推理 / 系统工程动态

vLLM 新增基于 Mooncake TransferEngine 的 Encoder Cache Connector，用 HTTP Registry、ZMQ 协调与 Pull 路径支持 Producer/Consumer 不共享文件系统的 EPD 部署，并提供双 GPU Tensor Equality 集成测试。模型 Offloader 还修复非整除 prefetch_step 时的静态 Buffer Slot 覆盖：Refill 只能沿释放 Slot 自己的 Module Chain 前进。SGLang 则让 PP 场景复用 TP 的 HiCache Event 聚合路径以减少 All-reduce；提交给出的单机 PP4×TP2 基准显示 TTFT 降低 7%、TPOT 降低 1%，但仍需在目标拓扑复测。

判断：今天的共同主题是资源所有权显式化：控制决策属于权威 Rank，静态 Buffer 属于确定 Slot，缓存 Tensor 属于可验证的传输会话，内存配额属于真实的 Request 或 Token 生命周期。

03

后端与云原生 / Rust / Golang 动态

Kueue 的重要变化是修复 Elastic Partial Scale-up 的 minCount 语义链路。KServe 为多副本 LLMInferenceService Scheduler 的 ServiceAccount 补上 Core Events 的 create/patch 权限：Leader Election Lease 原本能工作，但 Event Recorder 会持续报 Forbidden，属于可观测性缺口。最近 24–48 小时 Go 与 Rust 官方发布列表没有值得新增的稳定版本，今天不重复既有版本信息。

判断：控制面正确性既包括调度结果，也包括事件可观测性；但 RBAC 应保持最小权限，Event Recorder 只需 create/patch，不应顺手扩大到 update 或其他 Core Resource。

04

值得看的项目 / 论文 / 工具

  1. 跨 Rank Timeout Abort 的确定性状态机 — PR 给出了完整故障链：墙钟偏差造成队列不同步，进而让 Extend/Decode Admission 分叉，最终进入不匹配 Collective；修复复用请求广播而不新增 Collective。判断：适合直接转化为 TP Scheduler 的 Chaos Test：在超时边界注入 Rank Clock Skew，逐轮比对 Queue、Batch、Finished Reason 和 Cleanup Side Effect。
    SGLang PR #37143
  2. Triton Specialization Cardinality 回归模板 — 测试不只比较 Kernel 数值输出，还在 4096、4160、4224 三种 Context Length 下断言编译缓存数量不增长，直接覆盖长时运行才暴露的 Module Memory 泄漏形态。判断：建议把 Cache-entry Count、首次编译次数和已加载 Module Memory 纳入 Soak Test 指标，而不是只看短时峰值显存。
    SGLang PR #37093
  3. Unified-KV 容量账本的一致性检查 — 该改动同时更新 Pool Sizer、实际 Pool、可用量报告、首次 Admission 扣费与 C4 Ring 地址，展示了修复资源单位错配所需的完整触点。判断：可借鉴为静态校验：同一资源在 Capacity、Allocation、Admission、Release 和 Metrics 五处必须使用相同单位与 Gate。
    SGLang PR #38192
  4. Mooncake Encoder Cache 双进程传输测试 — vLLM 的集成测试覆盖独立 Producer/Consumer、HTTP Registry、Mooncake Pull 与跨 GPU Tensor Equality，比只验证 Connector 初始化更接近 EPD 的实际故障面。判断：上线前还应补超时、Producer 重启、过期 Registry、重复 Key、部分 Tensor 与跨版本 Schema 的故障注入。
    vLLM PR #41567
05

产业趋势与投资信号

最近 24–48 小时未核验到足够重大、且有公司一手公告支持的推理基础设施融资或并购。更值得关注的产业信号来自软件栈本身：当推理系统进入长上下文、推测解码、分离式部署和层级缓存阶段，竞争力越来越取决于长时稳定性与资源记账，而不只是单轮 Benchmark 峰值。

判断：评估推理平台时应把 24 小时以上 Soak、Collective 一致性、JIT Cache 基数、有效 Token Capacity 和缓存恢复正确性纳入采购与容量模型；短时吞吐无法覆盖这些成本。

06

行动建议

  1. 在 TP 超时测试中为各 Rank 注入亚毫秒级时钟偏差，断言 Abort 由单一权威 Rank 产生，并在同一调度轮次广播执行。
  2. 盘点 Triton Kernel 的 constexpr 与 Specialization Key，把来自请求长度、Stride 和动态 Shape 的无界整数改为运行时参数，并监控 Cache Entry 数量。
  3. 为 KV/SWA/C4 等内存建立统一资源账本，逐项核对 Sizer、Allocator、Admission、Release 与 Metrics 的计费单位和 Feature Gate。
  4. 扩展 MTP/EAGLE Offload 回归矩阵，覆盖共享与独立 Drafter Group、SWA 与非 SWA、粗细 Chunk、同步与异步完成路径。
  5. 验证 Kueue Elastic Partial Scale-up 时同时检查 Annotation、minCount、Webhook Mutation、Validation、Scheduler Admission 和 Scale-up Probe。
  6. 在 EPD Encoder Cache 压测中加入 Producer 重启、Registry 过期、Pull 超时和 Tensor Schema 不一致，并确认失败不会污染后续 Cache Hit。
