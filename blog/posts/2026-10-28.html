图像预处理提速要守住尺寸语义，ZMQ 就绪与 KV 元数据安全收紧

截至 2026-10-28 09:03（Asia/Shanghai）。重点看 SMG 多模态尺寸规划与直连 ZMQ 角色、Mooncake 元数据安全，以及流式失败和 HiSparse 内存边界。时间均为北京时间；main 合并不等于稳定版发布，作者基准与独立验证分开表述。

01

今日最重要

  1. SMG：MiniMax M3 一次缩放已合并，收益不等于尺寸策略不变 — #4681 于 10-28 07:27 合并，从原始图像头规划最终尺寸，在 lazy decode 做一次 uint8 bicubic antialiased resize。源图像长边超过 cap 时缩小，否则可把短边抬到 112；按 28 对齐，解码前拒绝超过 12,845,056 像素的规划结果。该路径绕过旧 min_pixels/max_pixels 面积策略，对齐也可能超过请求 cap。判断：作者共享 CPU VM 的闭环并发 4 测试报告 1080p/4K 吞吐 +36.0%/+37.8%，不是 GPU 或线上吞吐。RGBA 并发 8 的 p95 从 80.2 增至 96.2ms。升级先比较最终 grid、token 数、透明度与图像质量，不能把尺寸变化带来的工作量减少包装成等工作量提速。
    smg #4681
  2. SMG：直连 ZMQ 扩展 PD/EPD，bootstrap 缺失不能再报健康 — #4649 于 10-27 16:14 合并，为 TokenSpeed 直连 ZMQ 加入角色、引擎组大小与模型信息握手，支持 PD/EPD、控制调用及 tcp://；decode 按 pin 定位，prefill 按 room 定位。#4708 于 10-28 03:22 补上连接期检查：prefill/encode 注册要求每个引擎声明 bootstrap 地址，否则连接失败并保持不健康；decode/regular 不新增此要求。判断：这不是所有运行时都获得相同 ZMQ 能力。握手地址、实际 KV/embedding rendezvous 和执行 rank 应一起验收。tcp:// 的握手与数据端口没有认证，只应放在可信网络；不要把连接成功等同于跨节点数据面可用。
    smg #4649smg #4708
  3. Mooncake：Python HTTP 元数据服务改为网络绑定默认拒绝无认证启动 — #4472 于 10-27 19:41 合并。非 loopback 绑定未设 MC_METADATA_HTTP_TOKEN 时默认拒绝启动，显式 insecure opt-in 除外；引擎 HTTPStoragePlugin 同步带 Bearer 认证。新增 key/总字节、单 PUT body 和并发 body-read 上限，超出存储预算返回 507，过大 body 返回 413。判断：这是 Python HTTP metadata server 的修复，不包含 master 内嵌 C++ 同名服务，也不是数据面 descriptor 签名。预算不覆盖全部 Python 对象、等待连接和进程 RSS；部署前同时核对服务端与客户端 token，别用 insecure 开关绕过升级失败。
    Mooncake #4472

AI 推理 / 系统工程动态

SGLang #46513 于 10-28 08:53 合并：Rust native /generate 流遇 scheduler abort 时保留已有文本、计数与 finish_reason.abort 终帧，再发 [DONE]，与 Python 原生流一致；非流式、OpenAI 与 gRPC 的错误映射不因此统一改变。vLLM #61659 于 09:00 合并：HiSparse staged prefill KV 至少分配 256 行 backing，再返回原尺寸 view，避免 trtllm-gen sparse MLA 对小 buffer 越界读取，每 staged layer 增量最多 168KB。已检查 SMG 近期合并、重要 Issue 与 Release；最新正式版仍为 v1.13.0，新 Issue #4727 明确旧 tokenizer benchmark 未重跑当前 main，不能当本日性能证据。

判断：流终止必须同时检查终帧、错误语义和已发送文本，不能把带 abort 的 [DONE] 当成功。HiSparse 作者在 B200 上复现并验证特定 illegal-memory-access 修复，但独立 DBO invalid-argument 问题仍在；不要据此宣称 DBO 全部恢复。

后端与云原生 / Rust / Golang 动态

Kubernetes 10-27 官博宣布 Workload Conformance WG，拟建立按 minor 版本的 workload 行为规范、测试和工具；具体要求尚未定，目标在 2–3 个发布周期内形成首个稳定规范。Go 10-26 官博复盘 10-19 eMudhra 紧急更新：Go 1.27.3/1.26.10 已阻断受影响中间证书，这不是当天新发版。Rust 10-27 发布 variadic generics 微调查结果，收集 3300 多份回答，仍是语言设计输入，不是特性获批或稳定化。

判断：云原生规范关注的中断恢复与资源/API 行为适合提前纳入服务验收，但尚非新强制认证。Go 应核对实际服务二进制并重建部署，不能只升级构建机；Rust 调查不改变当前兼容基线。Go 复盘仅有日级日期，作为近两日背景，不宣称严格 48 小时内的新漏洞。

值得看的项目 / 论文 / 工具

  1. Mooncake C/Rust：一个对象可直接对应多个已注册 buffer — #4984 于 10-27 16:52 合并，将 multi-buffer batch put/get 暴露给 C ABI 与 Rust dlopen bindings，以 flat buffers/sizes 加每 key counts 表达分片。此前仅 Python 可用；Go bindings 尚未包含。判断：适合逐层分片 KV，避免调用方为单对象主动拼接。作者 GB300 双机 RDMA 往返 4GiB 字节一致，多 buffer 吞吐与单 buffer 接近，不是新带宽倍增；注册、所有权与调用期间生命周期仍需调用方保证。

产业趋势与投资信号

NVIDIA 与 Oracle 于 10-27 宣布 Vera Rubin NVL72 与独立 Vera CPU 在 OCI 正式可用；多吉瓦级扩容和 HGX Rubin NVL8 仍属规划。

行动建议

  1. 升级 M3 预处理前记录旧/新最终尺寸、grid、token 数与峰值内存；覆盖极端宽高比、RGBA、默认与自定义 cap，单独做图像质量回归。
  2. 直连 ZMQ 的 prefill/encode 逐 rank 校验 bootstrap 宣告与可达性；验证缺失地址拒绝注册、decode pin 生效及可信网络边界。
  3. 盘点实际使用的是 Mooncake Python HTTP metadata server 还是嵌入式 C++ 服务；分别评估认证覆盖，给请求 body、并发与进程内存设分层预算。
  4. 对 native 流式 abort 测试已发文本、finish_reason、usage、[DONE] 与非流式 HTTP 状态，避免客户端误重试或误报成功。
  5. HiSparse 回归把小 staged cache 越界与 DBO 其他异常分开复现；性能报告保留硬件、软件版本、模型裁剪和 dummy weights 条件。
