长上下文的系统税：历史扫描、巨型传输与调度饥饿

vLLM 消除结构化输出在长推理中的 O(n²) 历史扫描并修正混合 KV Block 几何；SGLang 用 HRRN 改善 Prefill 排队，并把超长 Mooncake 传输拆成有界批次。

01

今日最重要

  1. vLLM 把结构化输出的推理结束检测从全历史扫描改为增量扫描 — 结构化约束要等 Reasoning 结束后才启用，旧路径在每个 Decode Step、以及每个 Speculative Draft Position 反向扫描全部 Token 历史，单次 O(history)、长生成累计 O(n²)。新路径为可安全识别的 Parser 预计算单 Token 结束 ID，只扫描新增 Decode Window，并用单调 reasoning_ended 标记记忆结果；无法安全推导的 Parser 保留旧路径。判断：长 CoT 下，调度器中的线性历史扫描会从小开销演变成主导 CPU 税。所有逐 Token Hook 都应审计是否重复解析历史，并优先改成单调状态或增量游标。
    vLLM PR #55223
  2. SGLang 新增 HRRN Prefill 调度，在短任务优先与防饥饿之间取平衡 — HRRN 用等待时间与估算服务时间的比值排序：短 Prefill 更早执行，但长请求等待越久优先级越高。PR 的 2×8×B200、1P1D、混合 Agent 长上下文流量测试中，相对 FCFS 的平均 TTFT 从 24.2 秒降至 7.48 秒，P99 从 60.5 秒降至 55.48 秒，输入吞吐提升 39.58%；这些数字仍需在目标流量分布复测。判断：调度策略不能只优化均值。HRRN 适合服务时间可由未缓存输入长度近似、且长度长尾明显的 Prefill 队列；上线应同时设置等待老化观测和 P99 保护阈值。
    SGLang PR #32911
  3. SGLang 将超长 Mooncake 同步 KV 传输拆成有界索引批次 — 近 80 万 Token 请求可把主 KV 汇成一次约 30.30 GB 的 Mooncake 调用，即使地址范围只有 79 段，也可能在 Transport Slice 展开时耗尽瞬时资源。新路径默认每 1024 个 KV Index 形成一个有序批次，批内仍合并连续地址，首个非零结果立即失败返回；16 请求验证全部成功且未观察到 TTFT 或吞吐回退。判断：外层 Timeout 不能解决单次传输的资源峰值。分离式推理应分别限制 Index 数、Bytes、Range 数和 In-flight Batch，并让错误在最小批次边界可定位、可重试。
    SGLang PR #32758
  4. vLLM 避免 SWA Block 与主 KV Block 互质导致调度粒度膨胀 — 混合 SWA 与 MLA 时，SWA 从 Backend 最小 Kernel Block 起步，页面统一后可能与主 Block 形成很大的最小公倍数；示例中 1728 与 1536 把 Scheduler LCM 放大到 13824，破坏 Prefix Cache 粒度。支持未拆分主 Block 的 Backend 现在让 SWA 直接采用主 Block Size，使统一后的 LCM 保持在主 Block 粒度。判断：异构 KV 规格的统一不能只保证整除和显存对齐，还要显式约束 LCM 上界；否则每层局部合理的 Block Size 会在全局调度器中放大成缓存碎片。
    vLLM PR #53007
  5. Kueue DynamicQuotaOrchestrator 加入确定性比例配额分发 — 控制器从 Cohort 或 ClusterQueue 根向下解析配额子树，按 Flavor/Resource 建倒排索引，并用 Largest-remainder 方法做比例分配；CPU 采用 milliCPU 精度，其他资源用整数单位，余数用精确整数算术并以对象 UID 确定性打破平局。它还处理 Lending Limit 上限、多个 Orchestrator 冲突与失效接管。判断：动态算力配额要做到可重放：相同对象集合必须产生相同整数结果，不能依赖浮点舍入或遍历顺序。但该功能仍缺 Part 3 的 Watch、Event Mapper 与集成测试，现阶段不宜视为完整闭环。
    Kueue PR #15283
02

AI 推理 / 系统工程动态

vLLM 的 NIXL Connector 开始在 Metadata 与 Descriptor 中保留每个 Region 自己的 Stride、Block Capacity、Block Size、Cache-group Mapping 与名称，避免把独立几何的 Packed Region 压成单一布局，并支持 P/D 两端 Region Layout 不同的 Pure-MLA Peer。DCP 能力默认值也从隐式支持改为 False，Attention Backend 必须显式 Opt-in，使不支持的配置在加载权重前就被拒绝。CPU↔GPU Sync Debug 则扩展到检测 Non-pinned 或非 Dense Host Tensor 触发的隐式 Staging Copy。SGLang 新增 MLA/DSA Host Dedup 的 Pool 与 NCCL Broadcast 原语，但尚未接入 Scheduler，不能宣称功能已启用。

判断：跨设备路径的共同原则是声明式契约：传输描述符要携带真实几何，Attention Backend 要声明并行能力，Host Copy 要暴露隐式同步，基础原语与已接通功能要严格区分。

03

后端与云原生 / Rust / Golang 动态

KServe 为 v1beta1 InferenceService 增加顶层 spec.tracing API，包含 OTLP Endpoint、Sampler、Sampler Argument 与 Exporter 的默认化和准入校验；当前提交只建立 API 契约，尚未把配置注入 Workload 或为 Runtime 加埋点。LLMInferenceService 还修复路由组成员删除被无关 Peer 的终态配置错误无限阻塞：终止成员会先从 Controller-owned Route 释放，再进入其余 Desired-state Reconcile。最近 24–48 小时 Go 与 Rust 官方发布列表无新稳定版本。

判断：Tracing CRD 字段出现不等于端到端链路已可用，验收必须覆盖配置注入、SDK 初始化、Context 传播和 Collector 接收。Finalizer Cleanup 也应独立于普通配置 Reconcile，避免无关终态错误吞掉释放重试。

04

值得看的项目 / 论文 / 工具

  1. 逐 Token Hook 的复杂度审计模板 — vLLM PR 同时提供 Parser 安全降级与 Microbenchmark：可识别 Parser 的检查成本不再随 2K 到 64K 历史长度增长，无法安全推导单 Token 边界的 Parser 保留旧逻辑。判断：建议逐项审计 Reasoning Parser、Stop Matcher、Logits Processor、Structured Output 与 Tool Parser，记录每步复杂度和是否扫描全历史。
    vLLM PR #55223
  2. Mooncake 超长传输的多维上限设计 — 该案例证明 Range Count 低并不代表传输轻：少量连续 Range 仍可承载数十 GB 数据；按 Index 分批后保持地址顺序与批内 Coalescing。判断：可复用为传输层压测矩阵：固定 Range 改 Bytes、固定 Bytes 改 Fragmentation，并分别观测 Staging Peak、Session Failure 与 Partial Progress。
    SGLang PR #32758
  3. HRRN 在 Prefill 队列中的落地参考 — 实现用未缓存输入长度近似服务时间，并用等待老化避免纯短作业优先带来的长请求饥饿；PR 同时比较 FCFS、LPM、DFS-weight 与 HRRN。判断：复测时应按 Cache-hit Bucket、输入长度和租户拆分 TTFT，防止总体均值掩盖某类长请求或低命中请求的回退。
    SGLang PR #32911
  4. Dynamic Quota 的精确整数分配实现 — Kueue 用精确余数算术、资源 Scale 和稳定 UID Tie-break 实现 Largest-remainder，并显式处理 Subtree Cycle、所有权冲突和 Lending Limit。判断：适合作为多租户 GPU 配额控制器的算法参考，但要等 Watch 与集成测试闭环后再评估控制面收敛。
    Kueue PR #15283
05

产业趋势与投资信号

最近 24–48 小时未核验到足够重大、且有公司一手公告支持的推理基础设施融资或并购。工程信号更清晰：长上下文正在把瓶颈从 GPU Kernel 外溢到 CPU 增量处理、Prefill 排队、跨节点传输峰值和异构 KV 几何；平台能力要用端到端资源上界衡量，而不是单点 Kernel 峰值。

判断：面向百万 Token 场景的采购与容量评估，应增加每生成 Token 的 CPU 调度成本、单 Transfer Call 峰值、Prefix-cache 有效粒度、长请求饥饿时间和控制面配额收敛五类指标。

06

行动建议

  1. 对所有逐 Token 调度与解析 Hook 做复杂度审计，用 2K、16K、64K Reasoning Length 验证每步耗时是否随历史线性增长。
  2. 为 Mooncake/NIXL 传输同时设置 Index、Bytes、Range 和 In-flight 上限，并在超长共享前缀下验证顺序、首错传播和重试边界。
  3. 用真实流量回放对比 FCFS、LPM 与 HRRN，按输入长度、Cache Hit 和租户拆分平均、P95、P99 TTFT 与最大等待时间。
  4. 在混合 MLA/SWA/Mamba 模型启动时打印各 Group Block Size 与全局 LCM，超过阈值直接告警并拒绝隐式粒度膨胀。
  5. 验证 Attention Backend 的 DCP 能力采用显式白名单，确保不支持的组合在模型权重加载前失败。
  6. 跟踪 Kueue DynamicQuotaOrchestrator Part 3；在 Watch、Event Mapper 和集成测试合并前，只做实验环境验证，不纳入生产配额闭环。
