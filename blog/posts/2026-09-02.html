KV Cache 开始跨异构 TP 共享，但物理布局与信任链必须先对齐

vLLM 推进 Mooncake 异构 TP 共享，同时修复物理块长度导致的静默覆盖；SGLang 用实测定容 CUDA Graph 池，KServe 与 Kueue 则分别启动缓存验证和动态配额的契约建设。

01

今日最重要

  1. vLLM Mooncake Store 支持异构 TP 实例共享 KV — 新主干能力用固定 store_tp_size 定义稳定的逻辑 Store Shard，把对象布局与实例本地 TP Size 解耦。使用相同原生 KV Layout、相同 PP Size，且本地 TP 可整除共同 Store TP 的实例，可在 Prefill/Decode 或不同服务规格间共享同一 Key Namespace。判断：异构 TP 共享能减少重复 Prefill，但必须把 Store TP、KV Head Range、PP、Layout 与模型版本写进 Cache Identity；任一维度不一致都应拒绝命中。
    vLLM PR #53129
  2. vLLM 修复 Mooncake 物理块传输长度导致的静默覆盖 — 当 Scheduler 逻辑块大于 Attention Kernel 物理块时，旧路径展开了物理 Block ID，却仍给每个描述符附上完整逻辑 Page Size。Kimi-K3 的 768 Token 逻辑块对应十二个 64 Token 物理块，描述符因此重叠 12 倍，并在并发下覆盖相邻 KV。判断：这是典型的元数据正确、长度语义错误。所有 KV Connector 都应断言 Transfer Length 不超过物理 Stride，并用并发读写 Hash 检测静默覆盖。
    vLLM PR #54272
  3. SGLang 用 Warmup 实测定容 CUDA Graph Pool — 新改动在 Graph Warmup 中测量 Reserved Footprint，可选地在 Capture 前一次性预切连续区域，并加入 Sampling Prewarm，让全词表临时 Buffer 的需求在启动阶段暴露；同时修复 Borrowable Space 按 Segment 误计和归还路径问题。判断：Graph Pool 应由真实 Capture 与 Sampling 路径测量，而不是静态比例估算。启动报告需要同时展示 Pool、可借空间、KV 余量和碎片率。
    SGLang PR #36911
  4. vLLM 为递归 Tool Argument Parser 设置 128 层深度上限 — Gemma4 与 MiniMax M3 的手写递归语法可被深度嵌套模型输出耗尽 Worker Thread Stack 并终止进程。Rust Frontend 新增 Thread-local RAII Guard，在 128 个活动递归 Frame 时返回解析错误，并在正常、错误与 Unwind 路径恢复深度。判断：模型输出同样是不可信输入。Tool Parser、结构化输出和 JSON/DSL Grammar 都要有深度、节点数、字节数与解析时间预算。
    vLLM PR #54303
  5. KServe 建立 KernelCache 安全验证框架，但尚无真实密码学 — 第一阶段加入 Verifier 接口、SecurityConfig、Failure Policy 与统一 ShouldBlock 语义；目前只有 Disabled 模式，没有签名算法、验证消费者或运行时行为变化。后续模式将沿该接口接入。判断：接口先行是正确方向，但 Disabled 默认不能被误解为缓存可信。上线 KernelCache 前仍需签名主体、工件摘要、平台绑定、密钥轮换与 Fail-closed 策略。
    KServe PR #6099
02

AI 推理 / 系统工程动态

最近 24–48 小时没有新的 vLLM 或 SGLang 稳定版，以上变化均位于主干。Mooncake 的异构 TP 共享扩大了 KV 复用边界，却也让逻辑 Shard、物理 Block、Transfer Length 和实例拓扑的映射更复杂；同一时间出现的 12 倍描述符重叠修复说明，传输元数据必须由物理布局验证。SGLang 的 CUDA Graph Pool 改为从 Warmup 测量，也体现出静态容量公式正让位于真实生命周期观测。

判断：为远端 KV 建立可验证 Manifest：模型与引擎 Commit、Layout、Store TP、Local TP、PP、KV Head Range、Logical/Physical Block Size、Stride 与摘要全部入 Key 或伴随验证；容量则以 Warmup 和运行时水位双重校准。

03

后端与云原生 / Rust / Golang 动态

Kueue 合入 Dynamic Quota Orchestration KEP，提出从集群容量提供者发现容量，并按策略向队列分配动态配额；这只是 KEP，Release Note 为 NONE，尚非已发布功能。另一个 SparkApplication 修复在启用 Dynamic Allocation 时以 minExecutors 判断 PodsReady，避免 Executor 缩容后工作负载被反复超时重排。KServe Model Server 则支持监听证书文件并热重载 TLS，失败时保留现有证书。最近 24–48 小时没有新的 Go 或 Rust 稳定版。

判断：动态配额、弹性 Executor 与证书轮换都要求控制面基于真实最低承诺和当前 Generation 工作，而不是静态声明；应分别验证容量漂移、缩容稳定态与失败轮换。

04

值得看的项目 / 论文 / 工具

  1. Mooncake 异构 TP Layout Contract — PR 详细定义固定 Store TP、全局 KV Head Range、本地 Rank 到连续 Store Shard 的映射，以及共享实例必须满足的 PP 与拓扑条件。判断：适合转化为跨规格 P/D 的兼容矩阵和 Cache Key Schema；在无 Manifest 校验前不要允许自动跨 TP 命中。
    vLLM PR #53129
  2. SGLang CUDA Graph Pool Warmup 定容 — 覆盖连续预切、Sampling Prewarm、Segment 内空闲空间统计与 Borrow/Return 修复，并给出 GB300 推测解码场景中被隐藏的可借空间案例。判断：可直接借鉴为显存池启动诊断模板，但属于主干能力，需在目标硬件与真实模型形状上复测。
    SGLang PR #36911
  3. SGLang NIXL FILE devId 唯一性修复 — FILE Path Mode 曾在每次 Storage 调用中从 1 重启 devId；NIXL 描述符匹配不包含文件路径，并发批次可能误注销仍在飞行的 FD，触发 EBADF。修复改用全局单调 ID。判断：外部传输资源的身份不能依赖局部序号；Descriptor Key 必须全局唯一并覆盖资源生命周期。
    SGLang PR #34362
  4. KServe KernelCache Verifier Framework — 定义验证请求、结果、运行错误与失败策略的分离语义，为后续签名模式保留扩展点。判断：值得跟踪接口演进，但当前没有 Crypto 和 Consumer；安全评估必须等真实模式、密钥管理与调用链落地。
    KServe PR #6099
05

产业趋势与投资信号

最近 24–48 小时未核验到足够重大、且有公司一手公告支持的推理基础设施融资或并购。更明确的产业信号是缓存资产化：vLLM 让 KV 在异构 TP 实例间共享，KServe 开始为 KernelCache 建立验证接口，Kueue 则探索把集群容量转成动态配额。缓存、容量与签名正在从引擎内部细节上升为平台契约。

判断：未来的推理平台不仅要搬运缓存，还要证明缓存来自谁、适用于哪种拓扑、占用了多少可兑现容量。缺少身份、布局和信任链的共享缓存会把性能收益变成跨租户风险。

行动建议

  1. 为 Mooncake 跨 TP 共享设计 Cache Manifest，并用 TP1/2/4/8、相同 PP 和不兼容 PP 的读写矩阵验证命中与拒绝。
  2. 对所有 KV Connector 加入 Transfer Length <= Physical Stride 断言，并用并发写入后逐 Block Hash 捕获重叠覆盖。
  3. 在目标 GPU 上启用 SGLang Warmup 定容实验，记录 Graph Pool、Borrowable Space、KV 余量、碎片率和 Sampling 峰值。
  4. 审计 Tool/JSON/DSL Parser 的递归深度、节点数、字节数和耗时上限，并加入深度嵌套模型输出的进程存活测试。
  5. 跟踪 KServe KernelCache 真实签名模式与 Consumer；在 Crypto、Key Rotation 和 Fail-closed 落地前维持 Disabled 或隔离试验。
  6. 用容量波动与 Spark Executor 缩容轨迹评估 Kueue 动态配额 KEP，区分提案、实现 Feature Gate 和稳定版本三个阶段。
