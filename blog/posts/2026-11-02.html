准入排队必须进入路由决策，decode KV 回写补齐跨轮复用

SMG 提出按剩余准入窗口选择 decode 的候选，SGLang 将生成端 KV 写入外部缓存，vLLM 缩小 offload 元数据的 GC 扫描面。以近 24–48 小时一手进展为主，区分主线合并、草稿、mock 测试与真实引擎验证。

01

今日最重要

  1. SMG：decode 选择不能忽略网关等待队列 — #4811 于 11 月 2 日 00:54 UTC 新开，仍为 open draft。候选在已选 prefill 的兼容 decode 节点中，若有满有空，只把有剩余 room 的节点交给策略；计量同时扣除 claimed rooms 与等待 batch 所需 room。全部满、无 window 或未启用 gate 时保留旧行为，HTTP PD 不 claim room。作者 1P4D、每 D 窗口 8、24 闭环客户端的 CPU mock 中，least_load 吞吐由 5.03 到 6.42 req/s；共享构建机延迟有噪声，不是真实 GPU 容量结论。判断：负载打分要纳入网关未准入的积压，否则可能让满节点越来越便宜。先测有空有满、全满和宽 batch 公平性，不能把草稿当作已上线修复。
    smg #4811
  2. SGLang：decode KV 回写 linker，但跳过 prefill 已负责的前缀 — #46395 于 11 月 1 日 12:52 UTC 合并。decode radix cache 可把生成侧 KV 写到外部 store，同时按 prefill bootstrap 声明跳过其负责的 prompt 前缀；本地 radix 插入仍保留。此委托不等待持久化 ACK，prefill 写失败时后续轮次仍可能重算。作者 8 条轨迹、每条 6 轮的 agentic replay 中，Kimi Linear 与 DSv4.1-Flash 的 continuation prefill 命中率仅增加 0.644、1.036 个百分点，输出不逐 token 相同，不能解释为任务成功率或端到端加速。判断：跨轮缓存应分别计量 prompt 与生成输出的复用，以及重复上传和失败重算成本；强制清空设备缓存的测试与自然 agentic 流量要分开看。
    sglang #46395
  3. vLLM：offload 事件元数据从循环 GC 中移出 — #63927 于 11 月 1 日 18:27 UTC 合并，将每个 offload metadata entry 的 GC-tracked 对象从 3 个降为 0，使用 gc=False 的结构和 residency bitmask，保持集合与事件语义。作者 CPU mock serving 中，全量 GC 平均暂停从 106 降至 31 ms、ITL p99 从 119 降至 55 ms；模型 forward 与 GPU↔CPU 拷贝被模拟，未用 GPU，且每个主要实验臂仅 90 秒。判断：大容量分层 KV 的瓶颈也可能是主机元数据与 GC，而非搬运带宽。先联测 GC 回调、调度停顿与 ITL，再做真实模型长稳测试；不要直接全局关闭 GC。
    vllm #63927
02

AI 推理 / 系统工程动态

SMG #4807 于 11 月 2 日 01:03 UTC 合并，DeepSeek V4 effort prompt 改为对齐 vLLM v0.31.0 serving engine 自带 encoder，不再由 checkpoint 文件选择旧表。新测试覆盖携带旧 encoding 文件的本地目录；795 模型 fixture census 前后不变，因为那些目录没有 encoding 文件，不能说 795 模型被全面修复。昨日 HTTP PD bootstrap room 候选 #4772 已于 11 月 1 日 22:31 UTC 合并，仍未验证此 build 的 live SGLang PD 部署。已检查 SMG 近期 PR、合并、重要 Issue 和 Releases，最新公开 release 仍为 10 月 15 日 v1.13.0。

判断：模板一致性应以实际服务端实现为参照，并覆盖不同 tokenizer 来源。合并、fixture 回归和正式版本可用是三个不同状态。

03

后端与云原生 / Rust / Golang 动态

SMG #4787 于 11 月 2 日 00:47 UTC 合并：release-check 逐项读取 crates.io sparse index 与 PyPI 的已发布版本及发布时间，发现同版本发布后还有代码变更时失败，防止 publish dispatch 跳过版本却漏发更新。清单读取失败、registry 不可达或 REGISTRY=0 都不视为已验证通过。工具测试 98 项通过，但 release.sh tag 仍只运行版本检查，此新增项不会自动阻止打 tag。 Kubernetes #143680 于 11 月 1 日 18:49 UTC 合并，仅修改 Go 编写的 apiserver cost benchmark：交替 payload 避免相同内容的 GuaranteedUpdate 短路，区分并发 dry-run 与等待 etcd、watch cache、informer 链路完成的顺序持久化写入，并修正 WATCH 查询参数。

判断：Rust/Python 多包发布不能只核对 Git tag 和绿色 CI；必须核对 registry 实际交付。发布前需要显式跑完整 gate，不能把未访问包仓库当作检查成功。 压测也必须证明真实执行了写入，不能把幂等 no-op 或 dry-run 成绩当生产容量；此变更本身不是 apiserver 加速。

值得看的项目 / 论文 / 工具

  1. 取消回收测试：先确认 /loads 是请求之后的新样本 — SMG #4794 于 11 月 1 日新开，仍为 draft。旧 idle 检查可能立刻读到请求前缓存的 /loads 并误报 0 秒回收；候选先等待报告间隔与 poll deadline，在原 30 秒预算内判断新数据，直接读 live engine metrics 的 MoRI-IO 路径不加等待。证据包括 fake-clock 回归和历史 nightly 复盘，不是此 build 新跑真实引擎的结果。判断：很适合作为负载与取消验收的测试案例：样本时间、请求生命周期和资源释放应关联验证，数值为零本身不足以证明已释放算力。

产业趋势与投资信号

Cloudflare AI Search 的官方计费起始日为 11 月 1 日；这是 10 月 1 日 GA 公告中已预告的生效事件，不是今天新发布。计费区分 ingestion、storage 与查询；Workers AI embedding/reranking 纳入 AI Search 用量，而 generation、query rewriting 与外部模型仍走对应账户和服务。官方说明 ingestion 按最终 chunk 计量，重叠文本在每个 chunk 中重复计数。

判断：RAG 成本需要拆开检索平台、分块膨胀与模型调用，不应只比较 token 单价。预算用实际 chunk 分布、查询组合与生成调用核算，这只是产业计费结构观察，不构成投资建议。

06

行动建议

  1. 对 PD 准入压测同时记录引擎 running、网关 claimed/waiting rooms 和节点空闲却有人等待的比例，验证 batch room 需求而非只看请求数。
  2. 给 decode KV linker 补前缀委托、写失败、重算和跨轮命中测试，分开统计 prefill-only、decode-local 与外部 store 复用。
  3. 将 GC 暂停与 ITL 尾延迟关联，先复现元数据规模效应，再在真实 GPU、多轮负载和更长窗口下验收。
  4. 发布多语言包前核对 registry 已有版本与实际发布时间；取消测试先检查 /loads 样本是否覆盖请求之后的时间。
  5. 评估检索服务账单时分别估算 chunk overlap、存储、查询与生成费用，不把免费额度或打包服务误当全链路免费。
