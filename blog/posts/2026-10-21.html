PD 路由修复落地：缓存亲和性、首轮积压与超时边界

截至 2026-10-21 09:00（Asia/Shanghai）。重点跟进 SMG 昨日待合并事项的新进展，并核验推理引擎正确性、Go 安全补丁与云原生内存治理。下述 PR 合并不代表已发布稳定版；作者测试与厂商性能数据均未在本文独立复现。

01

今日最重要

  1. SMG：PD 缓存亲和性与首轮 backlog 修复已合并 — 昨日仍在评审的 #4014、#4015 已分别于 10-20 09:49、10-21 03:22 合并；后续 #4024 于 10-21 04:15 合并。未启用 --worker-overload-shed 时，cache_aware prefill 池不再先被绝对 overload veto 拆散，仍保留基于相对计数压力的 spill。新一轮 prompt 尚无回答时，prefill side 获得按 backlog 估算、每侧读取一次且最高 120 秒的等待窗口；运行中冻结与 decode 停滞的判定保持原时序。作者在 TokenSpeed 2P1D、并发 128 的长 prompt replay 中报告修复组合无 504，迁移比例降至约 0.6–0.7%，但这不是通用性能保证。判断：这是昨日提案的实质落地，不是重复旧闻。上线前同时测试缓存命中、队列饱和、空闲后突发与真实冻结，避免只恢复吞吐却拉长故障隔离。
    SMG #4014SMG #4015SMG #4024
  2. SMG：HTTP 请求预算耗尽不再触发跨 worker 重放 — #4064 于 10-21 07:09 合并：HTTP 普通路由、PD 及外部 provider 的请求自身超时返回终止重试的 504 call_upstream_timeout；连接失败与底层 I/O 超时仍可重试。#4060 于 06:11 合并，为网关自身 ZMQ 引擎连接补上从 dispatch 开始的请求超时，切断静默流并发送 abort、释放占用。两者的错误码与重试语义尚不完全统一：ZMQ collected answer 仍走 worker_stream_failed，其 PR 明确统一终止重试规则属于后续工作。判断：不要把‘有 timeout’等同于端到端预算正确。应按 HTTP/ZMQ、首 token 前/后、流式/非流式分别验证最终延迟、尝试次数及引擎残留请求；不能声称所有传输已禁止超时重放。
    SMG #4064SMG #4060
  3. vLLM：修复 symmetric collective 输出的存储别名 — #58154 于 10-21 02:21 合并。generic symmetric ReduceScatter 与 single-tensor AllGather 原先返回持久 scratch，相同 shape/dtype 的后续 collective 可覆盖仍在使用的结果；修复改为 clone 独立存储，并增加多输出保留及 CUDA graph replay 测试。Batched AllGather 与已有 AllReduce 不变，每次受影响调用增加一份输出大小的 D2D copy 和结果分配。判断：优先按正确性修复评估，而非吞吐优化。启用 symmetric memory 的多卡部署应比较连续 collective 输出、图重放与普通路径的一致性，再量化复制成本。
    vLLM #58154

AI 推理 / 系统工程动态

SGLang #37958 于 10-21 07:12 合并，默认开启符合条件的 prefill shared-read-done，让后一步共享表写入不必总等整个 forward；HiCache/LMCache、DeepSeek V4.1 等路径仍保留完整屏障，不能泛化为所有 prefill 加速。SMG #4062 于 06:11 合并，Rust SGLang servicer 只发送 SamplingParams 的 26 字段 API 前缀，并在 handshake 校验 positional layout，修复 SGLang 0.5.22 新增字段引起的错位；正文仍列真实 0.5.22 scheduler smoke 为待做。#4069 于 08:16 合并，将不支持的结构化输出约束提前拒绝扩展到 Rust SGLang/TokenSpeed servicer：已知禁用/不支持的 backend 返回 INVALID_ARGUMENT，而非引擎内 abort 后看似成功的空回答；未知 backend 不提前判断。

判断：优化必须携带适用矩阵；兼容性不能只看健康探针。把‘模型已启动、协议布局匹配、约束可执行、真实请求可完成’拆成不同验收项，尤其检查 Rust/Python 跨语言边界与 KV offload 配置。

后端与云原生 / Rust / Golang 动态

Go 官方发布记录注明 10-19 的 1.27.3 与 1.26.10 均含 crypto/x509 安全修复；Kubernetes #143201 于 10-20 12:01 合并，main 构建工具链跟进 1.27.3，但 kube-cross/go-runner 镜像更新当时仍待后续。Kubernetes #141299 于 10-21 06:29 合并，为 protobuf runtime.AllocatorPool 增加 beta、默认开启的 AllocatorPoolBufferCap：超过 256 KiB 的 buffer 使用后不回池，而交给 GC，并调整扩容公式为 max(n, 2*cap)。Rust 侧的实际工程变化见 SMG servicer 的布局握手与能力检查，而不拿旧版本发布填充。

判断：Go 升级要核对实际构建产物而非只改开发机版本。buffer cap 是池留存策略，不是对象大小限制；大对象控制面需同时观察 RSS 与 GC CPU，不预设固定内存降幅。上述 K8s main 合并不等于所有发行镜像已更新。
