推理系统技术日报 · 2026-08-18

调度开始同时解决确定性、阶段复用与内存层级

今天没有值得追逐的框架大版本；更重要的是，推理调度正从排队与批处理扩展到执行形态控制、RL 跨阶段复用和 MoE 权重的数据路径设计。

01

今日最重要

  1. CoRun 用固定执行形态实现确定性推理 — 论文将 Prefill 隔离执行，并以固定形状批处理 Decode，利用位置不变性与 CUDA Graph 避免动态批次改变 Kernel tiling 和浮点归约顺序；论文报告相对 Batch-invariant Kernel 方案，吞吐提高 15%–324%。判断：确定性不一定要由更慢的专用 Kernel 承担，也可以成为调度器的约束；但上线前必须验证模型、量化和硬件覆盖范围。
    CoRun 论文
  2. Rollplex 把 VLM RL 的 Prefix 计算移入 Rollout Decode 窗口 — 系统拆解 Reference 与 Training 阶段，把与响应无关的 Prefix 计算同 Rollout Decode 并行；通过阶段感知 HBM 管理和跨 TP 形态权重共享，论文在 32 张 H800 上报告相对串行共置加速 1.23–1.30 倍。判断：后训练推理的优化单位已从单个 Rollout 服务扩展为 Rollout、Reference 与 Actor Training 的整条 GPU 时间线。
    Rollplex 论文
  3. 高带宽闪存被重新评估为 MoE 权重层 — 两项工作分别研究 HBF 作为 GPU 内存层的可行性，以及同时使用 GPU–HBF 直连与 HBF–HBM–GPU 中继路径传送专家权重；双路径方案的代表性仿真报告 1.94 倍吞吐提升。判断：当专家权重增长快于 HBM 容量时，权重分层与预取可能改变 GPU 集群 BOM，但目前证据以架构分析和仿真为主。
    双路径 HBF 论文HBF 机会与挑战
  4. vLLM、SGLang 与 Kubernetes 近 48 小时无新正式版 — vLLM 最新正式版仍为 v0.27.1，SGLang 为 v0.5.17；Kubernetes 1.37 仍停留在 rc.0。判断：不重复报道旧版本；生产团队应利用安静窗口完善确定性、RL Rollout 和内存压力回归。
    vLLM ReleasesSGLang ReleasesKubernetes Releases
02

AI 推理 / 系统工程动态

CoRun 与 Rollplex 都把调度器从请求排序器提升为执行形态控制器。前者约束 Prefill/Decode 的形状和隔离方式，换取跨批次确定性；后者根据数据依赖拆开 RL 阶段，把 Prefix 计算塞进 Decode 的空闲算力，同时管理 HBM 生命周期与不同 TP 布局的权重共享。二者共同说明，仅观察 GPU 利用率无法解释有效产出，还要追踪确定性、阶段依赖、显存驻留和同步语义。

判断：未来推理运行时的核心抽象可能不再是单一 Request Queue，而是带数据依赖、形状约束、内存生命周期和 SLO 的执行图。

03

后端与云原生 / Rust / Golang 动态

Kubernetes 最新 1.37.0-rc.0 仍是预发布版本；Go 1.27 官方说明仍标注 DRAFT，Rust 稳定发布页近 48 小时没有新版本。对推理控制面而言，今天更值得做的是把固定形状 Decode、阶段感知调度和内存层级指标接入现有 Go/Rust 服务与 Kubernetes 观测链路，而不是追逐候选版。

判断：控制面应显式记录批次形状、CUDA Graph 命中、阶段等待、权重/KV 驻留和数据搬运带宽，否则新的调度收益难以定位和回归。

04

值得看的项目 / 论文 / 工具

  1. CoRun: Padding is Simple and Efficient for Deterministic LLM Inference — 从调度与固定执行形态而非 Batch-invariant Kernel 入手解决浮点非确定性。判断：适合正在做 RL、模型评测或可复现实验的平台精读，并应复现实测吞吐与确定性边界。
    arXiv
  2. Rollplex: Cross-Phase GPU Spatial Sharing for VLM Post-Training — 把 Prefix 计算跨阶段搬移，并处理 HBM 生命周期、不同 TP 布局与权重共享。判断：适合作为 VLM RL Runtime 的时间线和显存账本设计参考，不应只摘取最终加速比。
    arXiv
  3. Beyond Capacity: MoE Inference with Dual HBF Paths — 用两条独立路径并行传送专家权重，并通过提前确定专家来覆盖闪存读取延迟。判断：值得硬件与系统团队联合评估，但当前结果依赖模拟器和假定的数据路径能力。
    arXiv
  4. Exploring High-Bandwidth Flash for Modern LLM Inference — 系统分析 HBF 的读取带宽、写入性能、耐久性、批量和最小 GPU 数量之间的权衡。判断：适合建立 HBM–HBF–主机内存–存储的分层成本模型，避免把容量优势误当作免费吞吐。
    arXiv
05

产业趋势与投资信号

最近 24–48 小时未核验到足够重大且有一手公告支持的推理基础设施融资或并购。更值得跟踪的产业信号是：后训练工作负载要求 GPU 在 Rollout、Reference 和 Training 间精细复用；超大 MoE 又推动 HBM 之外的新权重层。这会把价值继续推向运行时调度、显存生命周期管理、高速互连和新型内存介质。

判断：下一阶段的基础设施溢价来自每张 GPU 在完整训练/推理流水线中的有效工作时间，以及每字节权重和 KV 的搬运成本，而不只是峰值算力。

06

行动建议

  1. 在固定随机种子之外增加逐 Token 输出一致性测试，并分别改变并发、批次形状、Prefix 长度和 CUDA Graph 路径。
  2. 为 RL/VLM 流水线绘制 Rollout、Reference、Prefix 与 Training 的 GPU 时间线，量化每阶段计算、等待与 HBM 占用。
  3. 评估固定形状 Decode 的填充浪费、Graph 命中率与确定性收益，和现有动态批处理做同流量 A/B。
  4. 建立 MoE 权重分层模型，纳入专家命中分布、预取命中率、读取带宽、写入耐久和 KV 干扰，不仅比较介质容量。
  5. 继续将 Kubernetes 1.37 rc.0 与 Go 1.27 草案限制在隔离 CI；生产版本保持不变。
