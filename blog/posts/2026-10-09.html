推理系统技术日报 · 2026-10-09

推理网关补齐准入边界，Go 安全更新与 KV 正确性值得优先验证

截至 2026-10-09 19:46（Asia/Shanghai）：SMG 与 vLLM 的主干修复聚焦准入和 KV 正确性，Go 发布安全更新；SMG v1.12.0 与 Gateway API v1.7.0-rc.1 仍为预发布版。已合并、已发布与开放提案分别标注。

01

今日最重要

  1. SMG 同时补齐 Router 总量上限与 vLLM Worker 准入窗口 — 今日 12:54 合并的 #2927 将未显式设置的 max-concurrent-requests 默认值设为每个可用 CPU Core 1024、至少 4096；显式 0 仍可关闭上限。19:38 合并的 #2926 让 Python 与 Rust vLLM Servicer 在 GetServerInfo 中报告 max_num_seqs，使 PD 准入门限生效，并增加逐 Decode Worker 的 smg_pd_admission_window 指标；缺失窗口时在注册阶段告警。判断：Router 全局在途上限与 Decode Worker 窗口约束不同层级。应联合压测内存、排队时延和拒绝率，确认窗口确实被上报，再校准显式上限；这些合并发生在 v1.12.0 预发布之后。
    SMG PR #2927：默认在途上限SMG PR #2926：vLLM 准入窗口
  2. vLLM 修复不同 P/D Block Size 下的 NIXL 接收后处理 — #58860 于今日 19:30 合并，修复 Prefill 的 Block Size 小于 Decode 时，接收端 KV 重排、尾部清零维度和重复处理等问题，原问题可能损坏 KV 或导致崩溃。enable_permute_local_kv 仅支持本地 LBNHC 布局，其他布局在握手时拒绝；Gemma 4 的剩余正确性问题仍依赖其他修复。PR 中的测试结果由作者提供，本报未独立复现。判断：先覆盖 Block Size 比例、KV Head 数、布局与模型组合，对比 Token 和 Logprob，再评估吞吐。一次接收后处理修复不能作为整个模型或跨布局链路已验证的依据。
    vLLM PR #58860
  3. Go 1.27.2 与 1.26.9 发布安全修复 — Go 官方于 10 月 8 日发布 1.27.2 与 1.26.9，安全修复涉及 go 命令以及 crypto/tls、html/template、net/http、net/textproto、os 包。官方发布历史同时列出各版本的其他缺陷修复。判断：按现有版本线更新 CI 工具链和构建镜像，重建并部署受影响服务。只更新开发机无法替换已上线二进制中的标准库；具体漏洞影响仍应结合公告和实际代码路径核查。
    Go 官方发布历史Go 官方下载
  4. Gateway API v1.7.0-rc.1 将重试配置纳入 Standard Channel — Gateway API v1.7.0-rc.1 已发布，GitHub 仍标记为 prerelease。发布说明将 retry.codes、retry.attempts 与 retry.backoff 一并提升到 Standard Channel；具体退避曲线和 Jitter 仍由实现决定。判断：字段进入 Standard Channel 与候选版本成为稳定版是两回事。试用前核对控制器支持，并联合验证重试次数、总超时和请求幂等性，防止网关与 SDK 多层重试放大负载。
    Gateway API v1.7.0-rc.1 Release
  5. SMG v1.12.0 预发布：区分版本能力与今日后续修复 — SMG v1.12.0 于上海时间今日 02:08 发布，标记为 prerelease，包含 Chain KV Index、快照中继、存活感知的缓存路由及 Rust Servicer 等能力。本文列出的默认在途上限、vLLM 准入窗口、启动预算和重试指标修复均在该版本发布后合并。判断：试用时固定版本或 Commit，并逐项确认所需修复已包含。不要仅凭 v1.12.0 标签推断今日主干修复已经交付；缓存状态、Worker 存活与协议兼容需要分别验证。
    SMG v1.12.0 Release
02

AI 推理 / 系统工程动态

SGLang #42998 于今日 19:17 合并，将 Chat Completions 下沉到 Router 的 /generate 路径，但仅限已验证的 AllText DeepSeek-V4 Renderer、Router 与 Worker 的模板参数一致、且无工具或媒体的请求，其余回退引擎原路由。SMG #2972 于 19:13 合并，让握手消息或引擎存活报告刷新默认 1800 秒的静默预算，同时保留默认 4 小时的总启动上限（设为 0 可关闭总上限）。19:14 合并的 #2968 将 Worker 重试退避指标从 Summary 改为 Histogram，桶覆盖 10 毫秒至 60 秒。

判断：协议下沉按 Gate 做正反例回归，避免把纯文本结果外推到工具或多模态。存活信号不能证明加载在推进，应保留总启动上限并观测阶段进度；指标类型变化后同步核对面板聚合和告警表达式。

SGLang PR #42998：受控 Chat 下沉SMG PR #2972：启动静默预算与总上限SMG PR #2968：重试退避直方图

后端与云原生 / Rust / Golang 动态

今日后端维护优先级是 Go 两条版本线的安全更新，以及 Gateway API 候选版本中的重试语义。Go 1.27.2 / 1.26.9 已正式发布；Gateway API v1.7.0-rc.1 仍处于预发布状态，其 Standard Channel 字段也需要具体控制器正确实现。

判断：将安全补丁与功能试用分开推进：先完成构建产物更新和服务回归，再在隔离环境验证网关重试。记录客户端、网关和上游各层预算，确保一次请求的总耗时与额外尝试次数可控。

Go 官方发布历史Gateway API v1.7.0-rc.1 Release

值得看的项目 / 论文 / 工具

  1. SGLang 外部 L3 缓存读取失败隔离：仍为开放提案 — #40896 截至截稿仍未合并。提案将外部缓存读取放入请求私有 Device Slots，跨 Rank 确认成功后才发布到 Radix Tree；失败请求返回 503，避免其他请求复用未就绪 KV。作者提供了故障注入结果，本报未独立复现。判断：值得参考其“加载完成后再发布”的正确性边界。评估时验证跨 Rank 一致性、失败清理与后续同 Prompt 请求，勿将开放 PR 写入已上线修复清单。
    SGLang PR #40896（Open）
  2. govulncheck：补丁验证的常用工具 — Go 官方 govulncheck 可结合代码可达性分析已知漏洞，帮助缩小需要人工复核的影响范围。它是成熟的既有工具，本日并无据此宣称的新版本发布。判断：将扫描纳入升级前后的 CI 检查，并结合实际构建配置与运行方式复核。无报告不构成完整安全证明，也不能替代工具链升级和服务重建。
    Go 官方漏洞管理文档
